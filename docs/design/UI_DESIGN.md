# OrionAI 前端 UI/UX 设计规范

本规范定义 OrionAI 前端的 Minimal Enterprise SaaS 设计体系。浅色中性表面、OrionAI 品牌蓝、清楚的信息层级和轻量交互贯穿认证与平台页面。所有新页面和既有页面改动均应遵循本规范，并保留当前业务逻辑、路由和权限行为。

## 1. 设计原则

- 让业务信息和主要操作优先进入视线；装饰只有在解释内容或帮助操作时才保留。
- 页面以白色和极浅灰色为主，品牌蓝用于主要操作、文本链接和选中状态。状态颜色只用于成功、警告和错误反馈。
- 通过字号、字重、留白和分组建立自然层级，不依赖大 Banner、连续的小型标签或卡片嵌套表达结构。
- 允许业务页面使用不同的信息布局；共用导航、基础控件、边界、状态与动效保持一致。
- 不新增重复组件、无效业务内容、装饰插画或依赖。当前未实现的控件只在真正有业务需求时创建。
- 对组件视觉的改动不得改变表单提交、搜索过滤、会话、菜单、路由或权限行为。

## 2. Design Tokens

令牌集中定义在 `frontend/src/styles/global.css` 的 `:root`。组件样式不得重复定义同义颜色、字体、间距或动效值；确有新语义时先扩展令牌，再在组件中引用。

### 字体、间距、圆角与效果

- 字体栈：`Inter, "Segoe UI", "Microsoft YaHei", sans-serif`；基础字号 `14px`。
- 字号阶梯：`--font-size-xs` 至 `--font-size-3xl`，范围 `12px` 至 `32px`。页面标题通常 `24–30px`，卡片标题 `14–16px`，正文 `14px`，辅助信息不小于 `12px`（纯装饰除外）。
- 行高：`--line-height-tight` `1.3`、`--line-height-normal` `1.5`、`--line-height-relaxed` `1.65`。
- 间距：`--space-1` 至 `--space-8` 对应 `4, 8, 12, 16, 20, 24, 28, 32px`。区块与控件间优先使用此尺度；流式内容宽度可使用 `min()`、`max()`、`clamp()`。
- 圆角：`--radius-control` `8px`、`--radius-card` `12px`、`--radius-panel` `16px`、`--radius-pill` `999px`。按控件、卡片、面板角色选用，不在相同角色中混用任意值。
- 阴影：默认卡片不使用悬浮阴影；仅浮层和对话框使用 `--shadow-menu`、`--shadow-dialog`。主要按钮使用轻量 `--shadow-primary` 或无阴影。
- 焦点：`--focus-ring`；过渡使用 `--motion-fast` `140ms ease-out` 和 `--motion-normal` `180ms ease-out`。

## 3. 字体与信息层级

- 页面标题用于说明当前任务或页面内容，不超过必要长度；标题不使用超大展示字号。
- 区块标题直接说明该区块内容。避免每个区块都加英文眉题或重复页面名称的小标签。
- 正文优先使用 `14px`，说明行高至少为 `1.5`；按钮、标签和次级说明保持可读，不以极小字制造精致感。
- 统一使用中等字重区分标题和动作，不在一屏内混用多种近似字重。
- 文案以自然、直接的中文为主。英文仅用于实际产品、技术或数据名词，不作装饰。

## 4. 页面布局与间距

- 平台主内容区最大宽度 `1440px`；桌面内边距采用 `32px` 设计令牌和流式宽度，窄屏采用更紧凑内边距。区块按信息关系分组，不为对称而添加内容。
- 认证页沿用产品说明与表单并列的桌面布局。产品说明保持简洁；认证表单宽度上限 `420px`，表单字段纵向排列。
- 平台桌面侧栏宽 `232px`，顶栏最小高度 `60px`。移动端侧栏转为可横向滚动的顶部导航，页面内容和操作仍位于同一主区域。
- 技能市场以页面标题、搜索、分类、结果列表为主序；不使用占据主要视野的 Hero 背景或装饰插画。
- `/agents`、`/sessions`、`/knowledge`、`/tools`、`/workspace`、`/settings` 当前共用建设中占位页。占位页保持简洁，不伪装成未实现的业务控制台。

## 5. 导航栏与顶部栏

- 桌面侧栏保持品牌标识、现有五个主导航入口、工作空间和用户菜单的结构与顺序；本规范不授权新增、删除或重排全局入口。
- 导航默认中性色。Hover 使用轻微中性底色；当前项使用品牌蓝文字和浅蓝底，辅以细指示线，不能只依赖颜色表达选中。
- 顶栏白底、单像素浅灰分隔线，内容只保留页面上下文、现有通知和用户菜单。控制高度和内边距，避免额外装饰。
- 移动端沿用顶部横向滚动导航，保持触控目标高度至少 `36px`，并提供可见选中态。

## 6. 基础组件与状态

现有代码的共用样式入口为全局 `.button`、认证 `.form-input`、`PlatformIcon`、`PlatformLayout`、`ProfileMenu`、`SkillCard` 和技能详情弹窗。优先扩展这些实现，不创建重复组件。

### Button

- 统一使用 `.button` 和 `button--primary`、`button--outline`、`button--secondary` 变体。高度、字体、圆角和焦点遵循全局令牌。
- 主按钮仅用于当前视图的主要提交/确认操作；次要动作使用描边或文本按钮。Hover 只改变前景、背景或边框；按下不缩放。
- 禁用态保留文字可读性、显示禁用指针，不触发动作。加载态在原按钮内部显示指示器。

### Input 与表单控件

- 输入框使用白底、浅灰边界、中性占位文字和统一控件圆角；高度至少 `40px`。Focus 使用品牌边框与焦点环。
- 认证输入、市场搜索使用相同文本颜色、边界、焦点、禁用和错误语义。Select、Textarea、Checkbox 尚无现存实例；未来需要时按同一令牌实现，不预先添加无用组件。
- 标签与控件保持关联。错误和成功信息用文字加语义颜色呈现，不只依靠色彩。

### Tabs、Dropdown 与 Dialog

- Tabs 使用简单文字标签、分隔线和品牌色指示当前项，不使用凸起的胶囊容器。
- Dropdown 采用白色浮层、浅灰边界和 `--shadow-menu`；保留键盘焦点、Escape 关闭和禁用反馈。
- Dialog 使用遮罩、白色面板、统一面板圆角和 `--shadow-dialog`；保留可访问名称、关闭按钮、Escape 和遮罩关闭行为。

### Card、Table、Tooltip

- Card 仅用于有明确分组或独立操作的内容。白底、细边框和 `--radius-card`；默认无阴影，Hover 不抬升。
- Table 当前没有现存实例。新表格应使用清晰表头、细行分隔、可读行高和一致的 hover/选中反馈，不给每个单元格添加卡片边框。
- Tooltip 当前没有现存实例。仅用于补充图标动作或被截断信息，不重复已经可见的标签；保持轻量浮层与键盘可访问性。

## 7. 图标

- 复用 `PlatformIcon` 和 `BrandMark`。线性功能图标保持描边圆端、圆角连接，`stroke-width` `1.6`，默认尺寸 `20px`。
- 普通图标使用 `currentColor` 和中性色。仅主要操作、导航选中或品牌标识使用品牌蓝。
- 不使用大量彩色分类图标、无功能图案或科技插画作占位；装饰图标对辅助技术隐藏，纯图标按钮提供可访问名称。

## 8. Hover、Focus、Active、Disabled

- Hover 提供低幅度颜色、边框或背景反馈，不移动卡片、不放大控件、不产生发光。
- Focus 对键盘用户必须清楚可见。组件可使用品牌色焦点环，不得移除焦点状态而不提供替代样式。
- Active/Selected 通过颜色、细边线或指示符与语义属性共同表达；当前导航使用 `aria-current`，筛选项使用 `aria-pressed`。
- Disabled 通过 `disabled`/`aria-disabled` 等正确语义阻止操作并显示禁用状态，不以透明度作为唯一辨识方式。
- 加载、空结果、错误与成功均应提供简短文字说明。空状态避免大面积插画与无意义 CTA。

## 9. 动画与交互

- 仅为颜色、边框、阴影和不超过几像素的位移添加快速过渡；采用 `--motion-fast` 或 `--motion-normal`。
- 菜单、弹窗使用轻量淡入和微小位移；避免缩放弹跳、连续漂浮、复杂光效和延迟主要操作的动画。
- 保留 `prefers-reduced-motion: reduce`，在系统请求减少动态效果时移除非必要动画并缩短过渡。

## 10. 响应式与可访问性

- 认证页在 `820px` 以下切换为单列；平台导航在 `800px` 以下切换为横向滚动，市场卡片在 `560px` 以下切为单列。
- 布局至少适配 `320px` 宽度。长文本可换行，横向导航可滚动，搜索/按钮/弹窗不得被裁切。
- 常用操作控件应保留清晰焦点、语义名称和足够触控面积；动态内容使用正确的 `role="status"`、`role="alert"` 或表单关联提示。
- 语义化结构和状态属性必须保留；纯视觉样式改动不能破坏现有 tab、menu、dialog 和导航的辅助技术语义。

## 11. 页面一致性检查

1. 已阅读本文件，页面继续遵循浅色中性基底与克制使用品牌蓝的体系。
2. 所有颜色、间距、圆角、阴影、字体层级和动效均使用全局令牌；没有重复硬编码或新增另一套视觉体系。
3. 页面信息层级清晰，没有无业务意义的大 Hero、重复标签、装饰插画或卡片嵌套。
4. 现有侧栏、顶部栏、按钮、输入、Tabs、Dropdown、Card 和 Dialog 风格一致，交互状态可见。
5. 桌面、平板、`390px` 左右窄屏下没有明显溢出、遮挡或难以触控的控件。
6. 键盘焦点、错误/成功/加载/空状态、减少动态效果偏好均得到保留。
7. 现有 API、路由、权限和业务行为保持不变；只优化实际存在的页面，不创建未实现的业务页面。
