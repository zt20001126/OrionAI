# 中英文界面切换实施方案

> 日期：2026-11-02（Asia/Shanghai）  
> 状态：已实施；验证结果见第 12 节。  
> 需求确认：已澄清英文覆盖范围。

## 1. 目标与设计原则

在 OrionAI 前端增加简体中文 / 英文切换。用户切换后，所有由前端维护的页面文案、按钮、表单校验、无障碍标签、加载/空/错误状态和前端错误提示立即切换；刷新页面及登录状态变化后仍保留选择。默认语言继续为简体中文。

沿用 React、TypeScript 和现有 UI 组件，不改变路由、业务流程或视觉体系。当前前端没有国际化依赖，因此首期采用轻量、类型约束的前端语言状态与文案目录，不新增第三方依赖。文案按功能域归类，动态插值、复数和日期/数字格式使用明确的本地化规则。

## 2. 已确认需求与范围

| 项目 | 已确认方案 |
|---|---|
| 可选语言 | 简体中文（`zh-CN`）和英文（`en`） |
| 默认语言 | 简体中文；未保存选择时保持当前行为 |
| 控件 | 未登录认证页和已登录平台都能直接找到切换按钮；切换不刷新页面 |
| 持久化 | 保存在当前浏览器的 `localStorage`；无可用存储时本次会话仍可切换 |
| 英文范围 | 前端自有 UI、前端校验/状态/错误提示、导航和辅助技术文案 |
| 可保持中文的内容 | AI 回复、后端响应及错误详情、数据库提供的技能/套餐等名称与说明、用户自行输入或保存的内容，以及外部支付页面 |
| 不在本次范围 | 后端国际化、数据库字段/迁移、账号级跨设备语言设置、浏览器自动推断语言、其他语言、RTL 布局 |

切换只改变展示文案与格式，不清空输入、不重置表单/训练/对话状态、不改写已有数据。前端生成的错误提示随语言切换；若错误详情直接来自后端，则按已确认范围保留后端原文。

## 3. 需求澄清记录

| 问题 | 确认结果 | 对方案的影响 |
|---|---|---|
| 英文是否覆盖 AI 回复与后端返回内容 | 只翻译前端界面；AI 回复及后端内容可以继续中文 | 不传语言请求头、不改提示词或后端错误处理；API 返回的动态文本原样展示 |
| 语言偏好保存位置 | 按需求默认使用浏览器本地保存 | 无需账号字段或数据库迁移；不同浏览器/设备不自动同步 |

## 4. 当前代码结构与依据

- `frontend/src/app/App.tsx` 集中选择认证页、平台壳层和各功能页，并包含会话恢复、导航确认等全局文案；适合作为语言提供器的应用入口。

- 页面文案分布在 `frontend/src/features/` 的认证、对话、技能、简历、提醒、记忆训练、会员和反馈功能中；日期格式目前有固定 `zh-CN` 的实现，例如 `frontend/src/features/conversations/ConversationHistory.tsx` 与 `frontend/src/features/membership/membershipUtils.ts`。

- `frontend/index.html` 初始 `lang` 为 `zh-CN`，且描述为中文；页面运行时的 `lang` 应跟随用户选择。
- `frontend/src/styles/global.css` 集中定义 `.button` 和设计令牌；切换控件沿用该体系。已阅读 `docs/design/UI_DESIGN.md`，方案不新增颜色、字体、导航入口或组件风格。

## 5. 架构与交互设计

### 5.1 前端语言状态

新增一个小型 `i18n` 模块，负责：

1. 定义 `zh-CN` / `en` 类型、消息目录和按语言取文案的函数。
2. 从固定 `localStorage` 键读取初始选择；无效值或读取异常时回退 `zh-CN`。写入失败不阻断当前页面切换。
3. 通过 React Context / Hook 让页面订阅语言变化；切换时同步更新 React 状态、本地存储及 `document.documentElement.lang`。
4. 提供可插值消息和 `Intl.DateTimeFormat` / `Intl.NumberFormat` 格式化入口，避免把固定中文格式散落在组件中。

翻译键按共用、认证、平台、对话、技能、反馈、会员、记忆训练、提醒、简历等命名空间组织。切换器使用现有 `.button` 变体与全局令牌：认证页放在认证面板右上角，平台内作为现有 `ProfileMenu` 的菜单项。这样在所有页面都可访问，也不增加顶栏内容或全局导航入口。按钮具备可见焦点、目标语言的可访问名称，并在窄屏保持可触控。

### 5.2 文案边界

- 组件里的固定标题、提示、状态和 `aria-label` 使用消息目录。
- 前端 API 封装自行生成的网络错误、HTTP 状态兜底和格式错误提示使用消息目录；`getSafeErrorDetail` 接受的后端字符串仍原样返回。
- 前端分类、订单状态标签、页面标题、访客默认称谓等属于 UI 的枚举或回退文案，需要按语言映射。
- API 返回的数据字段（如 `skill.name`、`plan.name`、会话标题/消息、提醒标题、简历内容）不在前端猜测翻译，也不改写保存值。
- 日期/数字等由前端格式化的数据采用当前语言；用户输入、API 载荷、价格币种和业务时区规则不变。

## 7. 接口与数据库变更审查

### 接口影响

**无 API 新增或契约变更。** 前端不发送 `Accept-Language`，所有既有请求方法、路径、请求体和响应结构保持不变。以下动态内容相关接口仍由现有后端提供文案，响应内容可继续为中文：

| 现有接口范围 | 操作 | 兼容性 / 说明 |
|---|---|---|
| `/api/auth/*` | 保持不变 | 后端认证成功消息和业务错误详情可继续中文；前端自有状态码兜底改为双语 |
| `/api/conversations/*` | 保持不变 | AI 消息、题目、会话标题和服务端错误详情按原样显示 |
| `/api/v1/skills*`、`/api/v1/users/me/skills*` | 保持不变 | 技能名称和说明为后端动态数据，不由前端翻译 |
| `/api/v1/membership/*`、`/api/v1/users/me/membership*` | 保持不变 | 套餐名称、后端消息/错误和支付提供商内容保持现有契约 |
| `/api/v1/reminders*`、`/api/v1/resume*`、`/api/v1/memory-training*`、`/api/v1/feedback` | 保持不变 | API 请求和响应契约不变；用户填写内容及后端返回文本按确认范围处理 |

### 数据库影响

**无数据库变更。** 不新增表、字段、索引或迁移。语言偏好存入浏览器 `localStorage`，不与账号数据同步；既有后端业务数据保持原值。

### 最小变更结论

- **可复用：** 现有 React 应用入口、`.button` 样式、顶栏与认证卡片布局、前端 API 错误封装和当前浏览器存储能力。
- **实际新增/修改：** 一个前端语言状态与文案模块、两个语言切换入口，以及所有前端自有 UI 文案和格式化调用点。
- **不新增依赖：** 仓库没有现有 i18n 包；首期语言范围只有两种，typed catalog + Context 足以满足即时切换、复数/插值和格式化，避免引入新框架。
- **不处理的内容：** 后端直返消息、AI 输出、服务端数据字段、用户输入内容和外部支付页面。
- **尚未确认的接口或数据决策：** 无。

## 9. 分步实施计划

### 步骤 1：建立语言状态和切换入口

- **涉及文件：** `frontend/src/i18n/localeStore.ts`、`frontend/src/i18n/LocaleProvider.tsx`、`frontend/src/i18n/messages.ts`、`frontend/src/i18n/LanguageSwitcher.tsx`、`frontend/src/app/App.tsx`、`frontend/src/features/auth/AuthPage.tsx`、`frontend/src/features/platform/ProfileMenu.tsx`、`frontend/src/styles/global.css`、`frontend/index.html`。
- **实施内容：** 建立双语类型与本地文案目录；从浏览器读取/保存选择；切换后即时更新订阅者及 HTML `lang`；认证区和现有用户菜单提供同一切换按钮。
- **前置依赖：** 无。
- **验收标准：** 未保存时页面为中文；点击切换后页面和 `document.documentElement.lang` 变为英文且不刷新；重新加载、退出并重新登录后仍为英文；存储不可用时控件仍可切换当前页面。
- **验证方式：** 新增语言状态与切换按钮单测；应用级集成测试；窄屏与键盘焦点人工检查。

### 步骤 2：翻译共用壳层、认证及基础提示

- **涉及文件：** `frontend/src/main.tsx`、`frontend/src/components/ConfirmationDialog.tsx`、`frontend/src/components/ToastProvider.tsx`，以及文件清单中认证、平台导航、用户菜单和设置组文件。
- **实施内容：** 将前端自有文案迁入对应命名空间；校验/状态错误兜底翻译；将服务端返回详情作为原文保留；翻译所有可访问名称和页面元信息。
- **前置依赖：** 步骤 1。
- **验收标准：** 登录、注册、密码重置、导航、用户菜单、设置、确认框、Toast 及各空/加载/错误状态都随语言切换；后端错误详情仍显示其原文。
- **验证方式：** `App.test.tsx`、`Platform.test.tsx` 和相关认证/菜单测试；检查键盘访问名称和语言切换后的焦点。

### 步骤 3：翻译功能页面并处理动态格式

- **涉及文件：** 文件清单中的对话、技能、反馈、会员、记忆训练、提醒和简历页面/API helper/组件。

## 10. 风险、假设与运行考虑

- **已确认边界：** 后端返回文字、AI 生成内容、用户内容和外部支付页面可能仍为中文；这是本次范围的明确选择，不作为前端翻译遗漏。
- **遗漏风险：** 文案散布于页面、API helper、ARIA 属性和格式化工具中。分域目录、硬编码文本检索和逐路由检查用于降低遗漏。
- **英文布局风险：** 英文标签通常更长。切换按钮、顶栏、侧栏和对话/表格区域需检查 `UI_DESIGN.md` 规定的窄屏尺寸，必要时只调整局部间距/换行，不改变全局导航结构。
- **本地存储：** 读取失败/无效值默认回中文；写入失败时保留内存状态。偏好不跨浏览器、设备或账号同步。
- **工作区状态：** 当前已有多处未提交改动，包含认证、会员、全局 CSS、文档及迁移文件；实现前应基于最新文件检查差异，并在同一内容上整合，不覆盖这些改动。
- **后端/API/安全/隐私：** 不新增网络字段或持久化数据；没有额外服务端风险。
