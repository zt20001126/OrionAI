# 数字人 A 股行情查询实现方案

> 日期：2026-11-05  
> 状态：已实现，真实模型端到端验证待执行

## 目标与范围

供内部验证的数字人单只 A 股行情查询：用户提供股票名称或代码，数字人返回可取得的最新价格、涨跌幅、币种和行情时间。接受非实时数据，但必须说明已知的时间和时效；无法确定时如实说明，不把查询时间当成行情时间。未提供股票时使用现有自由输入题卡追问；名称匹配多只股票时要求确认。无结果、停牌或行情不可用时说明实际情况，不编造数值。

第一版不包含港股、美股、交易、投资建议、历史走势分析或面向商业用户的发布。股票数据源建议先验证 AKShare；开源库本身不代表上游数据可商用。

## 现有结构

- `backend/app/modules/digital_human/agent/graph.py` 注册工具，复用现有 `agent_node`、`tool_node`、`output_node`。
- `backend/app/modules/digital_human/agent/tools/weather.py` 是数字人查询外部数据的现有示例；`backend/app/agent/nodes/tool.py` 将工具异常转换为不编造结果的观察。
- `backend/app/agent/schemas.py` 和 `backend/app/agent/tools/builtin/ask_user_questions.py` 已支持自由输入题卡；`frontend/src/features/conversations/QuestionWizard.tsx` 已展示输入框。
- `backend/app/modules/digital_human/agent/prompts/agent.md` 定义工具使用及回复规则；现有会话和检查点承载多轮追问。
- `backend/pyproject.toml` 当前没有 AKShare；加入第三方依赖前先验证具体接口、版本与项目 Python 环境。

## 设计和流程

```text
用户消息 → 数字人模型
         ├─ 缺股票信息 → ask_user_questions 自由输入 → 用户提交 → 恢复模型
         └─ 股票名称或代码 → A 股行情工具 → 匹配和查询 → 模型简短答复
                                              └─ 多个候选 → 请用户确认
```

工具输入股票名称或六位代码，输出结构化的匹配结果或行情：股票名称、代码、价格、涨跌幅、币种、行情时间、已知时效和数据来源。不同状态应明确区分：未找到、多个候选、无可用价格、上游失败。不得用空值或默认数字冒充行情；没有行情时间时返回“行情时间未知”，并向用户说明。

工具负责数据获取、匹配和字段转换；模型只根据工具观察组织语言。获取行情是外部 I/O，若选用的 AKShare 接口为同步调用，应避免阻塞 FastAPI 事件循环，并根据实际接口验证可用的超时方式；线程等待超时不等于底层请求被取消。模型工具选择是软约束，需真实模型验证，不能只依赖提示词保证调用。

先做数据源验证：核实 AKShare 具体 A 股接口能否查询所需证券、名称与代码、价格和涨跌幅，是否提供可信的行情时间及其时区，实测延迟、空值、网络异常及限流。若接口没有行情时间，第一版只能明确报告“行情时间未知”，不能承诺标明精确行情时间；若无法满足内部验证，则停止接入并重新选择数据源。不要把当前日期工具结果作为行情时间。

## 接口与数据库影响

复用 `backend/app/modules/conversations/router/router.py` 已有接口，路径带应用配置的 API 前缀：

| 接口 | 操作 | 用途及兼容性 |
|---|---|---|
| `POST /conversations/{conversation_id}/runs/messages` | 不变 | 提交用户问题，沿用认证、会员和响应契约。 |
| `POST /conversations/{conversation_id}/runs/answers` | 不变 | 提交现有题卡答案，恢复对话。 |
| `GET /conversations/{conversation_id}/runs/{run_id}/listen` | 不变 | 沿用 SSE 结果和题卡事件。 |

无数据库结构或迁移变更：现有 `backend/app/modules/conversations/models/models.py` 中的 `conversations` 和 `messages.content` 已承载会话消息和题卡，不持久化独立行情表，不新增字段。行情仅作为本轮工具结果和回答使用；既有会话历史按现有规则保存。

## 实施步骤与验收

1. **验证上游接口**：确认数据源授权、字段、行情时间、超时及频率限制，并记录验证结果。验收：明确接口及其能力；未知时效不会被标记为实时。若无法提供可靠的行情时间，按上述限制处理并向用户说明。
2. **实现工具**：在 `stock_quote.py` 实现输入校验、名称／代码匹配、行情读取和结构化结果；按实测选取依赖版本。验收：有效股票得到有来源的行情；无结果、多结果、空价格和异常分别得到可辨别的结果。
3. **接入数字人**：注册工具并更新提示词，复用 Text 题卡。验收：缺少股票时追问，确认后查询；回答包含价格、币种、可用的行情时间和已知时效，不给出未经用户要求的投资结论。
4. **验证回归**：工具层模拟上游，覆盖名称、代码、歧义、无结果、缺失时间／价格、超时和休市数据；图层覆盖追问恢复、工具调用及原有日期、天气、题卡行为；运行后端相关测试和 Ruff。用真实模型和上游人工测试一次，并记录行情时间和结果。不要将模拟测试视为实时接口或模型调用准确性的证明。

## 风险与运行考虑

- AKShare 的具体接口、上游可用性、时效和许可尚未验证；依赖可能增加安装体积并需要固定兼容版本。
- 单次返回全市场数据的接口可能耗时；先测量再决定是否需要缓存或更合适的查询方式，不预先引入持久化或后台任务。
- 日志只记录必要的错误类型和定位信息，不记录密钥；上游失败应明确反馈，不静默回退为旧价。
- 上线前需单独确认行情展示和商业授权；本方案仅用于内部验证。

## 实施验证记录（2026-11-05）

- AKShare 1.20.27 的 `stock_info_a_code_name` 实测首次加载约 11 秒，`stock_bid_ask_em` 单股报价实测约 0.22 秒；其股票列表在进程内由 AKShare 缓存，新上市或更名可能需要重启进程后更新。
- `stock_zh_a_spot_em` 全市场接口实测约 73 秒，未采用。所选单股报价不返回完整行情时间或延迟，工具明确返回未知，不推测休市或停牌状态。
- 实际调用股票 600519 的工具获得有效报价；上游返回没有行情时间，故无法验证行情新鲜度。行情来源为东方财富，授权和频率限制尚未确认，仅用于内部验证。
- 相关自动化测试和 Ruff 检查通过；测试使用模拟模型，尚未执行真实模型端到端验证。超时结束等待并不终止正在执行的同步请求，工具限制并发请求数量。
