# 个人资料设置实现方案

> 日期：2026-10-27（Asia/Shanghai）
> 状态：已按审阅方案实现
> 需求确认：基于截图、最新补充和现有代码形成方案；工程参数见第 12 节的非阻塞假设

## 1. 目标与背景

- **要解决的问题：** 当前 `/settings` 仍显示建设中占位页；`users` 表没有昵称和头像字段。
- **功能目标：** 新用户注册时统一使用项目默认头像；登录用户能查看并修改自己的昵称和头像。用户上传的头像写入 OSS，数据库保存该头像的公开访问链接。
- **预期最终效果：** 用户打开“个人设置”后看到可编辑头像和昵称，以及只读账号、创建时间和最后登录时间；底部提供“取消”和“保存”。未保存的输入或图片选择可取消；保存后重新读取的资料与界面一致。

## 2. 已确认需求

- **使用者 / 调用方：** 已登录用户；资料只能由当前用户读取和修改。
- **触发方式：** 从现有个人菜单打开 `/settings`。
- **输入：** 昵称；可选头像图片。
- **输出：** 昵称、账号、头像、创建时间、最后登录时间；保存后返回更新后的资料。
- **主流程：**
  1. 页面加载当前用户资料。
  2. 用户选择头像并编辑昵称；选择头像只做本地预览，点击保存后才上传。
  3. 保存时，后端校验输入，将新头像以对象级 `public-read` 权限上传至 OSS，并将其公开 URL 与昵称写入当前用户资料。
  4. 页面显示保存结果；OSS 图片通过保存的公开 URL 读取。
  5. 点击取消时丢弃未保存的昵称和图片选择，恢复到已保存值。
- **业务规则与边界：** 账号、创建时间和最后登录时间只读；昵称最多 20 个字符；上传头像后数据库直接保存 OSS 公共 URL。
- **异常行为：** 未登录返回现有认证错误；昵称或图片格式/大小不合法返回字段错误；未配置或不可用的 OSS 返回可理解的服务错误，不泄露凭据或 SDK 响应正文；没有已上传头像时使用工作区默认头像图片。
- **权限与数据范围：** API 使用现有 `get_current_user`；资料和头像路由均不接收用户 ID 路径参数，只操作当前登录用户。
- **约束：** 页面沿用 OrionAI Minimal Enterprise SaaS 规范；截图只作为结构和交互参考，不照搬其颜色、阴影、圆角或字体。

## 3. 范围

- **本次包含：** 新建用户资料业务模块；为 `users` 增加昵称和头像 URL；新注册用户及已有用户默认头像指向项目图片；迁移现有数据库；新增资料查询和资料保存 API；头像上传时写 OSS 并设置对象级公共读；将 `/settings` 占位页替换为资料设置页；更新 API/数据库文档；用 OSS 适配器单元测试、资料 API 集成测试和前端组件测试覆盖验证、OSS 读写和保存流程。
- **本次不包含：** 修改邮箱/账号、密码修改、头像裁剪、全站用户数据公开访问、全站菜单身份展示改版，以及个人设置页内新增退出登录按钮。头像本身按用户要求通过 OSS 公开 URL 访问；现有个人菜单中的退出入口保持原样。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `modules/users`（新增） | 个人资料 API、资料输入/输出 schema、验证与 OSS/数据库操作编排 | 依赖现有 `auth` 当前用户依赖、`auth.models.User` 和基础设施 OSS 适配器；Router 不写业务逻辑 |
| `modules/auth/models.py`（修改） | 持续拥有现有 `User` ORM 映射并增加昵称、头像 URL 字段 | 不搬迁 User 模型，避免改动依赖该模型的认证、会话、技能和 Agent 模块 |
| `infrastructure/storage`（修改） | OSS 上传增加对象 ACL 选项并生成/解析本项目对象的公开 URL | 只给用户头像启用公共读，不改变其他对象和 Bucket ACL |
| `features/platform`（修改） | `/settings` 个人资料界面、API 调用、局部表单状态 | 复用现有平台壳层、菜单入口和样式 token；不改变全局导航 |

### 关键流程

```text
新用户注册
  -> auth.repository.create_user
  -> users.avatar_url 默认值为 /avatar/default_avatar.png

ProfileSettingsPage
  -> profileApi
  -> /api/v1/users/me (Cookie)
  -> users Router -> UsersService -> users Repository + AliyunOSSObjectStorage
  -> 返回 avatar_url，浏览器直接读取图片
```

新注册用户通过数据库默认值使用 `frontend/public/avatar/default_avatar.png`；迁移也给已有账号填入同一默认路径。用户上传头像时，后端先以 `public-read` 对象 ACL 写入唯一 OSS 对象，再提交 `users.nickname` 和 `users.avatar_url`。若数据库提交失败，删除刚上传对象作为补偿；资料提交成功后尽力删除旧头像对应的 OSS 对象。Bucket ACL 保持原设置；上传账号需要 `oss:PutObject` 与 `oss:PutObjectAcl` 权限。数据库保留完整的公开 URL，不保存对象二进制。

头像和昵称通过一个 multipart 保存请求提交，以保持截图中单一“保存”操作的体验。当前 `backend/pyproject.toml` 没有 `python-multipart`，计划将其作为 FastAPI 文件表单解析所需的直接依赖加入。公开 URL 使用 Bucket 虚拟主机形式；配置的 `ALIYUN_OSS_ENDPOINT` 若为区域内网 Endpoint，生成 URL 时转换为对应公网 Endpoint。

## 9. 接口与数据库变更审查

### 接口影响

| 接口（方法 + 路径 / 事件） | 操作 | 当前定义位置 | 变更前后契约 | 复用判断与变更理由 | 兼容性 / 调用方影响 |
|---|---|---|---|---|---|
| `GET /api/v1/users/me` | 新增 | 现有相关自助 API 在 `backend/app/modules/skills/router.py`；本路由拟新增于 `backend/app/modules/users/router.py` | Cookie 认证；返回 nickname、account、avatar_url、created_at、last_login_at；未设置昵称时返回账号本地部分作为显示回退；新用户和已有用户的默认 `avatar_url` 为 `/avatar/default_avatar.png` | `GET /api/auth/session` 只恢复认证账号，不返回完整 profile，不适合扩张认证响应；settings 需要单独资料契约 | 新增，仅设置页调用 |
| `PATCH /api/v1/users/me` | 新增 | 拟新增于 `backend/app/modules/users/router.py` | Cookie + Origin 校验；multipart 包含昵称和可选图片；成功返回最新 profile；昵称最多 20 字符；图片类型/体积按假设约束；用户上传图片后返回并保存 OSS 公开 URL | 截图的保存动作需一次提交昵称和头像；JSON 无法高效承载图片，复用 Storage 上传需 multipart | 新增，不修改现有认证/技能调用方；新增小型 `python-multipart` 依赖 |
| `GET /api/auth/session` | 保持不变 | `backend/app/modules/auth/router.py` | 仍返回认证状态和 account，不增加资料字段 | 设置页用新的 profile endpoint，避免改变登录/会话契约 | 无兼容性变化 |

### 数据库影响

| 表 / 字段 | 操作 | 当前定义位置 | 用途与需求依据 | 复用判断与新增理由 | 迁移 / 回填 / 默认值 / 回滚 |
|---|---|---|---|---|---|
| `users.nickname VARCHAR(20) NULL` | 新增 | `backend/app/modules/auth/models.py`；迁移链最新为 `0008_add_image_agent` | 保存可编辑昵称；20 字符上限来自截图计数器 | `account` 是只读登录邮箱，不能替代用户设置的昵称 | `0009` 增加 nullable 列；旧用户保持 NULL，API/UI 以 account local-part 显示回退；downgrade 删除列 |
| `users.avatar_url VARCHAR(2048) NOT NULL` | 新增 | `backend/app/modules/auth/models.py` | 新注册和旧用户指向默认图；用户上传后保存 OSS 公开访问链接 | 用户明确要求数据库保存公开链接；不存二进制，OSS 继续承担图片字节存储 | `0009` 新增列并以 `/avatar/default_avatar.png` 填充旧用户、作为新记录默认值；downgrade 删除列。无新索引或外键 |
| `users.account`、`created_at`、`last_login_at` | 保持不变 | `backend/app/modules/auth/models.py` 及已有迁移 | 直接展示现有账号及时间字段 | 已能满足只读资料显示，不重复存储 | 不回填、不改约束、不影响现有登录 |

### 最小变更结论

- **可复用的现有接口 / 数据结构：** `User`、`get_current_user`、`validate_origin`、OSS 上传/删除适配器、`/settings` 路径、ProfileMenu 设置入口、工作区默认头像图片。
- **本方案实际新增或修改的最小集合：** 昵称和头像 URL 两列、一个迁移、两项当前用户资料 API、users 业务模块、OSS 对象 ACL/公开链接支持、一个 multipart 解析依赖、一个平台设置页和对应文档/验证。
- **排除的冗余设计及原因：** 不新建用户表，不移动现有 ORM `User` 类，不增设头像读取 API（OSS 图片为公开 URL），不改变 auth session 响应，不新增全局导航入口，不增加图片裁剪依赖。
- **尚未确认的接口或数据决策：** 无阻塞决策；头像格式/上限和昵称空值的显示回退作为可审阅假设列于第 12 节。

## 12. 风险、假设与运行考虑

- **非阻塞假设：**
  - 昵称 20 字符上限来自截图的 `10/20` 计数器；空值或全空格不允许保存。
  - 支持 JPEG、PNG、WebP，单文件最大 5 MiB；具体限制可在评审时调整。服务端按文件签名校验，不只信任扩展名或浏览器 MIME。
  - 旧账号的 `nickname` 可空；尚未设置昵称时展示 email 的 `@` 前本地部分（截断到 20 字符），不执行破坏性数据回填。
  - 页面时间按浏览器本地时区格式化为 `YYYY-MM-DD HH:mm:ss`；后端保留 timezone-aware 时间戳。
  - 新注册用户和已有用户均使用 `frontend/public/avatar/default_avatar.png` 作为初始头像；上传成功后以 OSS 公开 URL 替换数据库值。
  - 头像仅在个人设置页按本次需求使用；ProfileMenu 的缩写头像和昵称计算暂不改版。
  - 截图底部的取消/保存替代此前描述中的设置页退出按钮；现有 ProfileMenu 退出入口保留。
- **主要风险及应对：** OSS 与数据库没有分布式事务；用唯一新对象键、DB 失败补偿删除和提交后清理旧头像降低残留风险。公开链接可被任何持有链接的人访问；只给头像对象设置 `public-read`，不修改 Bucket ACL。OSS RAM 身份需有 `oss:PutObject` 和 `oss:PutObjectAcl` 权限。
- **安全 / 隐私 / 性能 / 可观测性：** 头像图片内容按需求公开；限制图片类型与字节数；不记录图片字节、密钥或 OSS 原始正文；验证带 Cookie 写请求 Origin。
- **发布、迁移或回滚：** 部署时需先升级 Alembic `0009` 再启用 API。回滚可降级迁移删除两列；已上传 OSS 对象需按 `users/{id}/avatars/` 前缀单独清理，避免误删同桶其他业务对象。前端部署必须包含默认头像静态资源。
