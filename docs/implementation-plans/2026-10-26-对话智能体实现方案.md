## 1. 目标与背景

- **要解决的问题：** OrionAI 已有会话与消息表及 Agent 目录骨架，但没有 Agent Runtime、模型 Provider 或对话 API。`.env` 中的 DeepSeek 配置目前未被 `Settings` 声明，因 `extra="ignore"` 而不会进入应用配置。
- **功能目标：** 在 OrionAI 实现一个可通过登录保护的后端 API 调用的基础对话智能体，参考 NexusAI `base_agent` 的 LangGraph、工具注册、结构化题卡等待与同会话恢复能力。
- **预期最终效果：** 登录用户可创建和查看自己的会话，发送文本并获得完整 JSON 回答；遇到影响任务的关键选择时可收到结构化单选题卡，提交选项后在同一会话继续运行。

## 2. 已确认需求

- **使用者 / 调用方：** 已通过 OrionAI Cookie 会话认证的用户；调用方为后端客户端，不包含本次前端页面。
- **触发方式：** 调用会话 API 创建会话、发送文本，或提交当前题卡答案。
- **输入：** 文本消息；恢复时提交题目 ID 到所选选项标签的映射。
- **输出：** JSON 完整结果，状态为 `completed` 并包含回答，或状态为 `waiting` 并包含题卡。首版不输出 SSE token 流。
- **主流程：**
  1. 用户通过现有 Cookie 认证后创建会话。
  2. API 以认证用户的 `users.id` 查询和授权会话，不接受客户端指定 `user_id` 或 LangGraph `thread_id`。
  3. Service 将用户消息按 `content.parts` 结构写入 `messages`，并将稳定的会话线程 ID 传给对话 Agent。
  4. LangGraph 校验输入、调用模型；如模型调用题卡工具则返回 `waiting`，否则提取最终文本并返回 `completed`。
  5. API 将助手回答或题卡写入消息表并更新会话 `updated_at`。
  6. 用户通过答案接口提交有效选项；服务校验答案与当前题卡完全匹配，在相同 Checkpointer 线程继续调用 Agent。
- **业务规则与边界：**
  - 复用已有 `conversations`、`messages` 表，不增加业务表或消息字段。
  - 题卡只支持单选；每批 1–3 题，每题四个标签不重复的选项，禁止自定义输入。
  - 一次只能恢复当前等待中的题卡；普通消息请求不能绕过待答题卡。
  - 对话模型来自已配置的 DeepSeek OpenAI-compatible 环境变量；模型与 Checkpointer 由应用生命周期创建并注入 Agent。
  - 题卡消息使用 `content.parts` 中的 `type: "question"` 部分；普通文本及答案使用 `type: "text"`。数据库不增加 JSON Schema 约束。
- **异常行为：** 未登录返回 `401`；会话不存在或不属于当前用户返回 `404`；当前并无待答题卡时提交答案返回 `409`；输入或答案结构无效返回 `422`；模型、配置或依赖服务不可用返回受控 `503`，不向客户端暴露密钥或底层异常文本。
- **权限与数据范围：** 所有会话与消息读写均按认证用户的 `user_id` 限定；题卡恢复的线程 ID 由服务端生成，并包含用户和会话作用域。
- **约束：** 遵循现有 FastAPI、SQLAlchemy、Alembic、LangGraph 项目结构；不实现前端、SSE、其他业务工具、RAG、多智能体注册或会话标题生成。

## 3. 范围

- **本次包含：** Agent Runtime、DeepSeek Provider 与设置接入、PostgreSQL Checkpointer 生命周期、认证依赖、会话/消息 API、复用现有数据库表、结构化题卡与答案恢复、API 与架构文档、相应测试。
- **本次不包含：** 前端聊天页面、SSE、会话删除/重命名、自动标题、图像消息处理、其他业务工具和跨会话记忆。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `app/agent` | LangGraph 状态、节点、图、BaseAgent 门面、题卡工具和提示词 | 接收 `BaseChatModel`、工具和 Checkpointer；不读取环境变量、不访问 ORM 或 FastAPI |
| `app/infrastructure/llm` | 根据 Settings 创建 DeepSeek OpenAI-compatible ChatModel | 基础设施适配；不承载对话业务 |
| `app/core/application.py` | 在 FastAPI lifespan 中建立并释放 Async PostgreSQL Checkpointer、Agent 及 Provider | 应用组合根；通过 `app.state` 注入服务 |
| `app/modules/auth/dependencies.py` | 解析现有 Cookie Session，返回当前用户 | 复用现有 Redis Session 与用户 Repository；无会话时统一拒绝 |
| `app/modules/conversations` | 会话权限、消息读写、答案校验、Agent 调用与 API DTO | Router → Service → Repository；Service 通过 BaseAgent 门面调用 Agent，不直接调用模型 |

### 关键流程

```text
HTTP Router
  -> 当前用户依赖 (Cookie / Redis / User)
  -> ConversationService
      -> ConversationRepository (SQLAlchemy)
      -> BaseAgent.ainvoke (LangGraph)
          -> input_node -> agent_node -> [tool_node -> agent_node] -> output_node
          -> AsyncPostgresSaver (按 user + conversation 生成 thread_id)
      -> 持久化 assistant text/question 到 messages.content.parts
```

图的拓扑在 `backend/app/agent/graph.py` 的 `build_conversation_graph()` 中定义并通过 `graph.compile()` 编译。FastAPI lifespan 在 `backend/app/core/application.py` 中创建 Checkpointer 和基础 Agent；`BaseAgent` 初始化时调用该构建函数并持有编译后的图，随后由会话 Service 调用 `BaseAgent.ainvoke()` 执行。当前没有从文件或数据库反序列化图的步骤。

答案恢复由独立 `POST /api/conversations/{conversation_id}/answers` 承担：Service 读取当前助手题卡、校验所有 question ID 和所选标签后，将规范化答案作为本轮 HumanMessage 提交到同一 `thread_id`。Checkpointer 保存 LangGraph 内部的 AI tool-call/ToolMessage 状态；`messages` 表继续作为用户可见记录。两者职责不同，题卡和工具内部消息不以工具调用细节暴露给客户端。

DeepSeek 接入使用 `langchain-openai` 的 OpenAI-compatible `ChatOpenAI`，通过 `Settings` 注入。`langgraph-checkpoint-postgres` 的 `AsyncPostgresSaver` 在应用生命周期初始化，并以同一 PostgreSQL 数据库保存跨请求的图状态。官方 Python 参考要求首次使用时调用 `setup()` 来建立 Checkpointer 自己管理的表；因此这些内部表由 Checkpointer 管理，不手写业务 Alembic 迁移。[LangGraph Checkpoint Python API](https://reference.langchain.com/python/langgraph/checkpoints) · [AsyncPostgresSaver.setup](https://reference.langchain.com/python/langgraph.checkpoint.postgres/aio/AsyncPostgresSaver/setup)

### API 契约草案

| 方法 + 路径 | 用途 | 请求 / 响应要点 | 权限与错误 |
|---|---|---|---|
| `POST /api/conversations` | 创建空会话 | 响应含 `id`、`title`、时间字段；首版 `title` 为 `null` | 必须登录 |
| `GET /api/conversations` | 列出当前用户会话 | 按 `updated_at DESC` 返回；请求支持有界分页 | 仅查询当前用户 |
| `GET /api/conversations/{conversation_id}/messages` | 读取消息 | 按消息 `id` 升序返回标准 `content.parts` | 非本人或不存在均返回 `404` |
| `POST /api/conversations/{conversation_id}/messages` | 提交文本并运行 Agent | 请求 `{ "message": "..." }`；响应含 `status` 与完成回答或题卡；若会话正等待题卡答案则 `409` | 必须登录且拥有会话；输入无效 `422` |
| `POST /api/conversations/{conversation_id}/answers` | 校验并恢复题卡 | 请求 `{ "answers": { "<question_id>": "<option_label>" } }`；响应格式同消息提交 | 必须登录且拥有会话；无待答题卡 `409`，答案不匹配 `422` |

响应继续使用 OrionAI 当前直接 JSON 响应和 `detail` 错误格式，不引入新的成功响应信封。会话创建与发消息分开；本次不提供删除、标题更新或 SSE 接口。

### 题卡消息格式

助手最终文本沿用现有格式：

```json
{"parts":[{"type":"text","text":"回答内容"}]}
```

等待响应在 JSONB `content` 中保存为：

```json
{"parts":[{"type":"question","questions":[{"id":"choice","title":"请选择","type":"SingleChoice","options":[{"label":"选项一","description":"说明"},{"label":"选项二","description":"说明"},{"label":"选项三","description":"说明"},{"label":"选项四","description":"说明"}],"allow_custom_input":false}]}]}
```

这只是扩展现有 JSONB `parts` 的消息内容，不改变字段或数据库约束；API DTO 会校验完整题卡结构。用户选择记录为普通文本 part，避免新增消息表或非必要列。

## 9. 接口与数据库变更审查

### 接口影响

| 接口（方法 + 路径） | 操作 | 当前定义位置 | 变更前后契约 | 复用判断与变更理由 | 兼容性 / 调用方影响 |
|---|---|---|---|---|---|
| `POST /api/conversations` | 新增 | 无；API 聚合在 `backend/app/api/router.py` | 创建当前用户的空会话，返回会话 ID 与时间 | 现有 auth/health API 无会话创建能力 | 新接口，不影响现有接口 |
| `GET /api/conversations` | 新增 | 无 | 按当前用户、最近更新时间列出会话 | 复用 `(user_id, updated_at DESC)` 索引 | 新接口，使用有界分页 |
| `GET /api/conversations/{id}/messages` | 新增 | 无 | 返回会话消息，按 `id` 升序 | 复用现有 messages 表及索引 | 新接口；所有权检查后再返回 |
| `POST /api/conversations/{id}/messages` | 新增 | 无 | 接收文本，持久化 user message，返回 completed answer 或 waiting questions | 现有 API 无 Agent 调用入口；新增模块化聊天 API | JSON 同步返回；题卡等待时后续须调用答案接口 |
| `POST /api/conversations/{id}/answers` | 新增 | 无 | 接收题目 ID 与选项标签映射，验证后继续同一 Checkpointer 线程 | 普通消息接口无法区分并严格校验题卡恢复 | 新接口；无待答题卡或错误状态返回 409 |
| 当前 `/api/health`、`/api/auth/*` | 保持不变 | `backend/app/api/router.py`、`modules/auth/router.py` | 契约不变 | 新增认证依赖而非改造既有业务行为 | 兼容；只调整依赖定义导入 |

### 数据库影响

| 表 / 字段 | 操作 | 当前定义位置 | 用途与需求依据 | 复用判断与新增理由 | 迁移 / 回填 / 默认值 / 回滚 |
|---|---|---|---|---|---|
| `users.id`、`users.account` | 用户 ID 改为 Snowflake；账号保持不变 | `auth/models.py`、`0002_add_users_identity_id.py`、`0004_snowflake_primary_ids.py` | 会话归属使用 BIGINT 用户 ID；认证 Cookie 仍解析 account | 账号和认证行为不变 | `0004` 重编号现有用户并同步业务外键；回滚恢复 Identity |
| `conversations.*` | 保持字段及索引；主键改为 Snowflake | `modules/conversations/models.py`、`0003_create_conversations_and_messages.py`、`0004_snowflake_primary_ids.py` | 会话创建、归属、列表排序和更新时间 | 现有业务字段满足需求 | `0004` 重编号会话并同步消息外键及 Checkpointer 线程；Service 更新 `updated_at` |
| `messages.*` | 保持字段及 JSONB `parts`；主键改为 Snowflake | 同上 | 保存用户文本、助手文本与题卡 | 不新增内容表或列 | `0004` 重编号消息；题卡结构由 Pydantic API/Agent Schema 校验 |
| LangGraph Checkpointer 内部表 | 新增/版本升级，由 `AsyncPostgresSaver.setup()` 管理 | 当前不存在；依赖首次运行时建立 | 保存 tool-call、waiting 和线程状态，供多个 API 请求及服务重启后恢复 | 业务 messages 表只存用户可见记录，不能单独保存完整 LangGraph 节点状态 | 由 Checkpointer 管理内部 schema；应用 DB 账号需具备建表/迁移权限；无手写 Alembic downgrade |

### 最小变更结论

- **可复用的现有接口 / 数据结构：** Cookie Session、`users.id`、`conversations`、`messages.content JSONB parts`、LangGraph、`app/agent` 空目录。
- **本方案实际新增或修改的最小集合：** 一个基础 Agent Runtime、一个 DeepSeek Provider、一个认证保护的 conversations API 模块、Checkpointer 生命周期与相应测试/文档。
- **排除的冗余设计及原因：** 不建第二套消息/会话表；不新增 agent_id；不复制 NexusAI Runner 的 SSE、任务队列、事件日志或计费层；不为 Checkpointer 内部表手动维护重复 Alembic DDL。
- **尚未确认的接口或数据决策：** 无。非阻塞假设：会话由独立创建接口建立；首版不生成标题；每批题卡单选且四个固定选项；答案接口与消息接口分离。

## 10. 分步实施计划

### 步骤 1：接通模型配置与 Provider

- **目的：** 让应用通过现有 DeepSeek 环境变量创建注入式 ChatModel。

- **实施内容：** 添加与当前 LangGraph 兼容的 `langchain-openai`；Settings 声明 SecretStr API Key、base URL、model；Provider 封装 ChatOpenAI 初始化和未配置异常。

### 步骤 2：实现 BaseAgent 图、工具和题卡协议

- **目的：** 在 OrionAI `app/agent` 建立与参考 BaseAgent 等价的最小对话执行骨架。
- **涉及文件：** `backend/app/agent/**` 所列新增配置、错误、schema、状态、图、节点、提示词、工具、线程 ID 和运行时文件。

- **前置依赖：** 步骤 1。
- **验收标准：**
  - [ ] 空白/超长输入被拒绝；无工具普通文本可产生非空 completed answer。

- **验收标准：**

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 会话标题保持 NULL；用户通过独立创建会话接口开始聊天；答案只支持题卡给定标签；单个会话串行交互，不在首版提供并发消息/幂等键协议。
- **主要风险及应对：**
  - AsyncPostgresSaver 的 `setup()` 会创建/迁移其自有内部表，数据库账号需有相应权限；升级其包版本时需检查 Checkpointer schema 兼容性。
  - `messages` 保存面向用户的记录，Checkpointer 保存完整图执行状态，两者都会含对话上下文；不要记录消息正文或 API Key 到日志。
  - 删除会话/用户时，数据库级联会清理业务 messages，但不会自动清理 Checkpointer 内部线程；本次没有删除接口，未来增加删除时必须调用 Checkpointer 的线程删除 API，避免残留状态。
  - 长对话会持续增长 Checkpoint 上下文并可能触及模型上下文上限；本次不引入摘要或复杂裁剪策略，超限时返回受控模型错误并在后续单独规划上下文策略。
- **安全 / 隐私 / 性能 / 可观测性：** Cookie 身份只用于服务端解析；所有业务查询按 user_id 过滤；thread_id 不由客户端提供；模型/工具日志只记录错误类型和会话标识，不记录用户正文、答案或密钥。
- **发布、迁移或回滚：** 无新的业务 Alembic 迁移；部署需安装新增依赖，并确保 PostgreSQL 可供应用 lifespan 建立 Checkpointer schema。回滚代码时，Checkpointer 内部表由对应库版本管理；不应在未确认数据保留策略前自动删除这些表。
