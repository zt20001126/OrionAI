# 数字人 A 股 K 线 MA 指标实现方案

> 日期：2026-11-10（Asia/Shanghai）
> 状态：已实现；功能范围内自动化验证通过；窄屏人工检查及周／月K真实上游检查待执行
> 需求确认：已确认实现位置、默认周期和显式触发规则

## 1. 目标与背景

- **要解决的问题：** 当前数字人可以查询并展示 A 股日／周／月K，但图表没有移动平均线。
- **功能目标：** 用户明确要求 MA／均线时，基于当前 K 线计算指定 MA，并在文字回答和 K 线图中展示；未要求时不计算、不返回、不绘制 MA。
- **预期最终效果：** 默认 K 线行为保持不变。用户要求均线但未指定周期时显示 MA5、MA10、MA20、MA60；指定其中周期时只显示所指定的周期。曲线来自 AKShare 返回的前复权收盘价。

## 2. 已确认需求

- **使用者 / 调用方：** OrionAI 数字人助手。
- **触发方式：** 用户查询 K 线时明确要求 MA 或均线；例如“查询茅台日K并加上 MA”。仅要求走势或 K 线时不触发。
- **输入：** 现有股票、周期和日期区间参数；内部工具参数增加可选 MA 周期列表。
- **输出：** 现有 K 线消息 payload 可选增加 MA 数据；助手文字摘要也可引用工具计算结果。
- **主流程：**
  1. Agent 根据用户请求判断是否明确要求 MA；没有明确要求时不设置 MA 周期。
  2. 复用 `get_stock_kline` 获取前复权 K 线；用户要求 MA 时，额外取可计算起始均线所需的历史收盘价。
  3. 后端按日／周／月数据点分别计算简单移动平均，并只将用户所选区间的 K 线和对齐的 MA 值放入同一图表 payload。
  4. 现有 Agent 响应、消息持久化和 MESSAGE 流继续传输该 payload；前端在蜡烛图上绘制均线和图例。
- **业务规则与边界：** MA 是简单移动平均（SMA），公式为当前及之前 N 根前复权收盘价的算术平均；N 为 5、10、20、60。未指定周期时使用全部四种；用户指定子集时只计算该子集。每条 MA 与返回的 K 线按位置对齐；前置历史不足 N 根时该位置没有 MA 值，不以不完整窗口冒充 MA。
- **异常行为：** 保留现有 K 线查询的无数据和上游失败行为；MA 计算不产生行情默认值。MA 未被请求时不附带空数组或空值字段。
- **权限与数据范围：** 复用当前数字人及会话权限；只查询用户请求的单只 A 股和日期区间。
- **约束：** 不新增独立 Agent 工具、HTTP 端点、数据库字段或第三方依赖。

## 3. 范围

- **本次包含：** 对现有 K 线工具增加显式 MA 参数；计算和传输 MA5／10／20／60；在现有 SVG 图表叠加均线；扩展消息 payload 类型和相关测试。
- **本次不包含：** EMA、MACD、KDJ 等其他指标；自定义任意窗口；独立 MA 工具；实时行情或投资建议。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `stock_kline.py` | 根据 `ma_periods` 可选参数计算指定周期的 MA；用前复权收盘价 | MA 是 K 线查询的确定性派生值，放在现有行情工具内，不另建 Agent 工具或服务层。 |
| Agent 能力提示 | 根据用户原始请求决定是否设置 MA 周期 | 只负责调用意图，不自行计算指标。 |
| `KlineChartPayload` | 校验可选 MA 系列及其与可见 K 线的对应关系 | Agent、持久化消息、SSE 事件共用同一结构。 |
| 数字人图表组件 | 将收到的 MA 序列叠加在现有蜡烛图上 | 只负责绘制，不重新计算 MA。 |

### 关键流程

```text
用户请求
  -> 数字人 Agent 判断是否明确要求 MA
  -> get_stock_kline(stock, period, range, ma_periods=[])
  -> AKShare qfq K 线；有 MA 请求时补取起始日期前的历史收盘价
  -> 计算选定周期的简单移动平均
  -> KlineChartPayload（K 线 + 可选 moving_averages）
  -> 现有 AgentResponse / 消息持久化 / kline_chart MESSAGE
  -> 前端 SVG 蜡烛图及可选均线
```

工具参数使用可选 `ma_periods`（允许值 `5 | 10 | 20 | 60`，默认空列表）；空列表代表不计算。通用均线请求使用四个默认周期，明确指定 MA 周期时只传入指定周期。这样省去单独工具调用，并让“未明确要求不算”成为工具默认行为。

为确保区间第一根可见 K 线的 MA60 完整，需要在可见区间前读取最多 59 根同周期历史 K 线。AKShare 通过日期范围查询，工具按日／周／月设置足够的日历缓冲，计算完成后裁掉缓冲数据，只返回用户请求的区间；默认仍只返回最近 60 根，最多 300 根的限制只统计可见 K 线。若股票上市时间不足，MA 序列在累计满 N 根有效收盘价前为 `null`。

payload 建议形状：

```json
{
  "moving_averages": [
    {"period": 5, "values": [null, 10.2, 10.4]},
    {"period": 20, "values": [null, null, 9.8]}
  ]
}
```

每个 `values` 与 `candles` 等长并按索引对应；未请求 MA 时省略 `moving_averages`。图表图例只展示 payload 中的 MA 周期。曲线颜色和线型使用现有全局令牌，不新增依赖或独立图表系统。

## 10. 分步实施计划

### 步骤 1：为现有 K 线工具增加按需 MA 计算

- **目的：** 仅在用户明确要求时计算所需周期的 MA。
- **涉及文件：** `stock_kline.py`、`capabilities.py`、`backend/app/agent/schemas.py`、对应后端单元测试。
- **实施内容：** 增加可选 `ma_periods` 参数（默认空列表）；更新 Agent 能力规则；基于前复权收盘价计算简单移动平均；按需扩大 AKShare 查询的历史起点以取得可见区间前最多 59 根 K 线；最终仅返回用户区间内可见 K 线及对齐的 MA 数据。
- **前置依赖：** 无。
- **验收标准：**
  - [x] 未请求 MA 时返回的图表不包含 `moving_averages`，也不执行均线计算。
  - [x] 通用 MA 请求产生 MA5／10／20／60；点名周期只生成点名周期；数值符合 N 根前复权收盘价算术平均。
  - [x] 日期区间内首根可见 K 线使用区间前历史计算；历史不足 N 根时对应值为空，不返回部分窗口均值。
  - [x] 默认可见 K 线仍为最近 60 根；MA 预热数据不会出现在图表或触发可见 K 线数量上限。
- **验证方式：** `test_digital_human_stock_kline.py` 使用固定 K 线数据检查无 MA、MA 值、指定子集、预热区间及不足窗口。

### 步骤 2：将可选 MA 纳入现有图表消息契约

- **目的：** 使工具计算出的 MA 经由现有 Agent、持久化和流式事件到达前端。
- **涉及文件：** `backend/app/agent/schemas.py`、`backend/tests/unit/test_conversation_kline_schema.py`、`backend/tests/unit/test_digital_human_agent.py`、`backend/tests/integration/test_conversation_endpoints.py`。
- **实施内容：** 在 `KlineChartPayload` 增加可选 MA series；验证周期属于支持集合且 values 与 `candles` 等长；扩展既有测试确认 Runtime、历史消息与流式 MESSAGE 保留同一 payload。会话 service 和 event schema 继续复用共享 payload，不另加分支。
- **前置依赖：** 步骤 1。
- **验收标准：**
  - [x] MA payload 通过 `AgentResponse`、会话消息和 SSE schema 校验；未包含 MA 的旧图表仍有效。
  - [x] 流式图表事件和持久化历史中的 MA 数据与工具结果一致。
  - [x] 非法 MA 周期、非有限均线值或与 K 线长度不匹配的数据被 schema 拒绝。
- **验证方式：** 后端 schema、Agent Runtime 和会话集成测试。

### 步骤 3：在现有 K 线 SVG 上绘制 MA

- **目的：** 用户请求 MA 后能在对话图表中辨认各条均线。
- **涉及文件：** `frontend/src/features/conversations/conversationApi.ts`、`DigitalHumanConversation.tsx`、`DigitalHumanConversation.test.tsx`、`digitalHuman.css`。
- **实施内容：** 扩展前端 MA series 类型；按序列的非空值在 K 线图坐标系内绘制折线；展示存在于 payload 中的 MA 周期图例；MA 数据缺失时保持现有纯蜡烛图。曲线配色复用现有全局颜色令牌，并通过图例和线型区分。
- **前置依赖：** 步骤 2。
- **验收标准：**
  - [x] 带 MA 的 SSE 和历史图表都绘制相同均线；不带 MA 的图表无均线和图例。
  - [x] 图例只展示实际返回的周期；均线为空值的前置区段不产生 SVG 坐标或曲线。
  - [ ] 既有蜡烛图、文字消息和窄屏布局不回归。
- **验证方式：** 前端 K 线流／组件测试、TypeScript 检查、ESLint、Prettier；人工检查桌面及 320px 视口。

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 用户笼统要求 MA／均线时计算全部 MA5／10／20／60；明确点名周期时只算所点周期。尚未有足够历史数据时由图表显示可用区段，助手说明未形成 MA 的周期数据不足。
- **主要风险及应对：** 如果只使用当前可见的 60 根数据，区间第一根的 MA60 会缺少窗口历史，因此请求 MA 时向 AKShare 查询更早数据，计算后再按可见区间裁切。AKShare 前复权历史数据可能随公司行为调整；MA 与对应 K 线采用同次响应数据。
- **安全 / 隐私 / 性能 / 可观测性：** MA 是 O(返回行数 × 4) 的简单本地运算，不新增远程服务。无 MA 请求时不增加行情查询区间。
- **发布、迁移或回滚：** 无数据库迁移或依赖变化。新增 MA 字段可选；旧前端忽略新增字段，新前端读取旧历史消息时没有均线也可正常绘图。
