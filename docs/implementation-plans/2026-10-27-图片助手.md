# 图片助手实现方案

> 日期：2026-10-27（Asia/Shanghai）
> 状态：已实现并完成本地验证
> 需求确认：已澄清；不支持参考图上传

## 1. 目标与背景

- **要解决的问题：** NexusAI 的图片智能体依赖旧项目的 Agent Runtime、附件存储和任务结果设施，不能直接放入 OrionAI。OrionAI 已有通用 Agent、技能市场和对话框架，但目前没有可运行的图片 Agent。
- **功能目标：** 在 `backend/app/modules/agents/image_agent/` 按 OrionAI 的 Agent 分层新建图片助手，并复用通用 Agent 的输入校验、题卡协议、工具注册和会话 Checkpointer 能力。
- **预期最终效果：** 用户能在技能市场添加“图片助手”，从“我的技能”进入专属会话，用文本描述生成电商商品主图或详情页图片；缺少画幅时先回答题卡；成功图片保存到私有 OSS 并在会话历史中显示。现有通用对话助手继续按原流程运行。

## 2. 已确认需求

- **使用者 / 调用方：** 已登录且已将“图片助手”添加到“我的技能”的用户。
- **触发方式：** 在技能市场添加图片助手，再从“我的技能”点击“使用”；会话绑定所选技能，后续消息由对应 Agent 处理。
- **输入：** 用户文本描述；本期不接收参考图片。
- **输出：** 普通咨询返回引导文本；生图请求返回完成文本和可在消息历史中查看的图片结果；缺少画幅时返回现有单选题卡。
- **主流程：**
  1. 对话创建请求指定已添加的 `image_agent` 技能，服务端将技能代码固定到会话。
  2. Agent 复用通用输入校验和 Checkpointer；专用意图节点判断是否立即生图，并把商品描述整理成提示词。
  3. 用户未指定尺寸时，复用公共题卡协议询问画幅；答案通过当前会话线程恢复。
  4. 生图工具调用 TokenHub Hy-Image，校验并下载其图片结果，保存到私有 OSS，记录任务结果。
  5. 对话服务保存图片结果引用；前端读取消息后，通过受登录保护的图片结果接口显示图片。
- **业务规则与边界：** 保留 NexusAI 图片助手的商品图意图判断、提示词整理、可识别参数提取、画幅追问与 TokenHub 调用行为；仅文本生图，不支持参考图、图片编辑、图片分析或附件上传。
- **异常行为：** 未配置 TokenHub 或 OSS、上游超时/拒绝/限流、无效结果地址或文件类型、下载过大及存储错误均返回稳定且不泄露凭据或上游原始响应的错误消息；任务状态可标记失败。
- **权限与数据范围：** 只有拥有该技能的用户可创建对应会话；会话权限沿用现有所有权校验；图片结果接口按登录用户和结果记录校验所有权，OSS Bucket 保持私有。
- **约束：** 图片 Agent 放在 `backend/app/modules/agents/image_agent/`；遵守 OrionAI 的 Router/Service/Repository 和 Agent 执行边界；不新增大型依赖；优先复用通用 Agent 能力。

## 3. 范围

- **本次包含：** 新建图片 Agent 图、状态、参数 Schema、提示词、节点、TokenHub Provider 和生图工具；新增必要的图片结果持久化与私有读取接口；以技能代码绑定对话运行时；注册“图片助手”到现有技能市场；前端增加可运行入口并渲染图片结果；配置、迁移、文档和测试。
- **本次不包含：** 参考图上传、附件表及附件 API；图像理解/编辑；新增技能市场机制；前端导航重构；真实 TokenHub/OSS 密钥或线上连通性验证。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `app.agent.runtime.protocol` 与 `app.agent.schemas` | 定义对话 Service 可调用的统一 Runtime 契约，以及可选图片结果引用 | `BaseAgent` 和新 `ImageAgent` 都实现该契约；不依赖 Router、ORM 或外部 Provider。 |
| `app.modules.agents.registry` | 依技能代码返回已注册 Runtime；组合根注入通用对话和图片 Runtime | conversations 依赖 Agent registry，不导入具体图片实现。 |
| `app.modules.agents.image_agent` | 自有 State、Schema、图、提示词、节点、参数规则、TokenHub 工具和 Runtime 门面 | 依赖共享 `app.agent` 协议、题卡及工具执行能力；不访问 FastAPI/ORM。Provider 仅负责外部 HTTP 与结果下载。 |
| `app.infrastructure.storage` | 已提供 `AliyunOSSObjectStorage.put_object` / `get_object`、稳定对象类型和受控错误 | 图片 Agent 注入延迟创建的 Storage factory，直接复用；不在本功能中重新实现 SDK 适配，也不在 lifespan 创建 OSS 客户端。 |
| `app.modules.agents.image_agent` 的持久化/API层 | 保存生图任务状态、结果对象键和所有权；授权后读出图片字节 | Repository 访问任务表；Service 执行业务/授权；Router 只做请求响应。 |
| `app.modules.conversations` | 在创建时保存 `skill_code`，按会话选择 Runtime，并持久化图片结果消息块 | 只依赖 Runtime 协议及 Registry；既有通用助手继续使用原 Runtime。 |
| `app.modules.skills` | 幂等添加 `image_agent` 市场记录 | 复用现有 `skills` / `user_skills` 和 API，不把 Runtime 实现存入技能表。 |
| 前端技能和对话功能 | 创建带技能代码的新会话、显示对应助手名、渲染授权图片结果 URL | 复用市场卡片、通用对话页面、题卡组件和全局设计令牌。 |

### 关键流程

```text
我的技能 -> POST /api/conversations(skill_code=image_agent)
         -> 会话绑定 image_agent -> ConversationService -> AgentRegistry -> ImageAgent
         -> input 校验 -> 意图/提示词节点 -> 参数题卡（如需要）
         -> generate_image 工具 -> TokenHub -> 受限结果下载 -> OSS 私有保存
         -> 图片任务结果 -> 助手消息 image_result 块 -> 前端受权读取图片
```

- **复用边界：** 直接复用 `create_input_node`、`ToolRegistry`、`create_tool_node`、`ask_user_questions`、`QuestionPayload`、共享 Agent 错误类型及对话 Checkpointer。现有 `output_node` 只产出纯文本，图片助手需要专用结果映射节点；意图判断与 TokenHub 工具是图片领域逻辑，不能用基础对话的模型节点替代。
- **结果持久化：** 新增 `task_results` 表保存运行状态、用户/会话/消息归属和 OSS 对象元数据；`messages.content` 只保存公开结果 ID/状态，不保存图片字节或 OSS 密钥。图片通过认证 API 读取，接口校验结果记录的用户归属后调用 `AliyunOSSObjectStorage.get_object` 读取内容，避免公开 Bucket 或长期公开 URL。
- **会话选择：** `conversations.skill_code` 初始默认 `general_chat`，新建会话时接收可选技能代码。创建及每轮消息均校验该用户仍拥有已发布技能。将技能写入会话可使历史会话稳定使用原 Agent，也避免客户端每轮请求随意切换技能。
- **题卡恢复：** 图片尺寸问题采用通用 `QuestionPayload` 与 Checkpointer；线程 ID 增加 `skill_code` 以隔离不同 Agent 的状态。答案从已经持久化的对话消息/检查点上下文恢复，不另建图片专用问答协议。
- **配置与安全：** `deepseek` ChatModel 复用现有 `OpenAICompatibleChatModelProvider` 用于意图和提示词整理；新增 TokenHub API Key、模型、Endpoint 和超时配置。OSS Settings、适配器和 SDK 依赖均已存在。TokenHub 图片 URL 仅允许 HTTPS 和源项目的受限腾讯云域名规则，禁用重定向，校验 MIME/大小，日志不写密钥或上游正文。

- **可复用的现有接口 / 数据结构：** 技能市场全部 API、`skills`/`user_skills`、Conversation API、`messages.content` JSONB、`QuestionPayload`、公共题卡工具与 SSE 协议。

## 12. 风险、假设与运行考虑

- **非阻塞假设：** “图片助手”继续沿用源项目定位，生成淘宝/电商商品主图及详情页图；沿用 NexusAI 的 TokenHub Hy-Image Provider 与对应默认模型/接口配置；图片结果保存并在消息历史展示是生成能力的一部分。
- **主要风险及应对：** 生图 API 延时可能超过单次 HTTP 常见等待时间；继续走现有 SSE 及心跳，不额外新增异步队列。若后续压测证明仍不足，再以独立需求引入后台任务。
- **安全 / 隐私 / 性能 / 可观测性：** TokenHub key 用 `SecretStr`；结果 URL 域名和 MIME/大小严格校验；重定向关闭；OSS 对象保持私有；结果读取校验用户；日志只记录错误类型、结果 ID 和上游 request ID，不记录密钥、完整提示词或上游响应体。
- **发布、迁移或回滚：** 部署需设置 TokenHub Key、OSS endpoint/Bucket/凭据并升级 Alembic。回滚时应先禁用图片助手并清理/导出 task_results 和 OSS 对象，再移除会话 Agent 外键/列；保留已有 general_chat 会话。无数据回填到 task_results。
