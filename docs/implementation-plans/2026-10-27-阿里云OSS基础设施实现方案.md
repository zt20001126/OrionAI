# 阿里云 OSS 基础设施实现方案

> 日期：2026-10-27（Asia/Shanghai）  
> 状态：已实施（2026-10-27）
> 需求确认：已澄清；本方案仅覆盖通用 OSS 基础设施，当前不接入应用业务

## 1. 目标与背景

- **要解决的问题：** OrionAI 的 `backend/app/infrastructure/storage/` 目前没有 OSS 适配实现；NexusAI 的 OSS 客户端与图片、文献、简历领域规则耦合在各自适配器中。
- **功能目标：** 在 OrionAI 建立一层可复用的阿里云 OSS 对象操作适配器，供后续业务模块显式调用。
- **预期最终效果：** 基础设施代码和配置就绪，但没有业务模块调用它、应用启动时不创建 OSS 客户端，也不发起 OSS 网络请求。OSS 配置留空时，现有功能照常启动。

## 2. 已确认需求

- **使用者 / 调用方：** 后续需要对象存储的后端业务模块；本次没有实际调用方。
- **触发方式：** 后续业务显式创建适配器并调用对象操作；本次不增加触发入口。
- **输入：** OSS endpoint、Bucket、AccessKey ID/Secret，以及相对对象键、字节数据、内容类型和可选元数据。
- **输出：** 上传、下载、查询元数据、复制、删除和按前缀分页列举对象的结果。
- **主流程：** 后续调用方提供已校验的对象键与内容 -> 适配器在配置完整时创建 OSS SDK Bucket 客户端 -> 调用 SDK -> 将结果转换为基础设施类型，或抛出脱敏存储异常。
- **业务规则与边界：** 通用适配器不定义图片格式、文件大小、用户归属、staging/final 生命周期或业务对象键规则；这些属于未来调用方。
- **异常行为：** 配置不完整时，显式构造适配器应抛出“未配置”异常；OSS SDK 错误转换为不包含密钥或上游响应内容的存储异常；对象不存在可区分处理。
- **权限与数据范围：** Bucket 使用私有访问策略；基础设施不负责用户授权，调用方必须先校验对象归属。
- **约束：** 不得在 `create_app` 或应用 lifespan 中初始化 OSS，也不新增 Router、业务模块、数据库模型或迁移。

## 3. 范围

- **本次包含：** 通用 OSS 基础设施代码、配置字段、环境变量示例、SDK 依赖及使用假 Bucket 的单元测试。
- **实施结果：** 适配器支持 put/get/head/copy/delete/list，带对象根前缀、下载大小上限、异常脱敏、404 区分和 HTTPS endpoint 校验。
- **本次及后续实现均不包含：** 移植 NexusAI 的图片、文献 PDF、简历照片存储类及其领域异常；将 OSS 注入应用生命周期；新增业务 API、数据库持久化、公开 URL 或预签名 URL；连接真实 OSS 验证。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| `app.core.config.Settings` | 保存 OSS 凭据、endpoint、Bucket、对象键前缀，并提供配置完整性判断 | 不依赖 storage；敏感字段使用 `SecretStr`。 |
| `app.infrastructure.storage.object_storage` | 定义存储错误类型及对象元数据/分页结果等稳定返回类型 | 不依赖 FastAPI、业务模块或 OSS SDK。 |
| `app.infrastructure.storage.aliyun_oss` | 构造 `oss2.Bucket` 并实现通用对象操作；关闭下载响应；将 SDK 异常映射为脱敏异常 | 只依赖配置、通用存储类型和 `oss2`；不依赖 `app/modules`。 |
| 未来业务调用方 | 决定对象键的业务含义、授权、文件校验、生命周期和数据库引用 | 依赖 storage 适配器；storage 不反向依赖业务模块。 |

配置字段拟命名为 `aliyun_oss_access_key_id`、`aliyun_oss_access_key_secret`、`aliyun_oss_endpoint`、`aliyun_oss_bucket`、`aliyun_oss_object_prefix`，并以 `aliyun_oss_configured` 判断前四项是否齐全。凭据、endpoint 和 Bucket 默认空字符串；对象前缀默认 `orionai`，因此无 OSS 配置不会影响 `Settings` 构造。

通用类型拟包括 `ObjectStorageError`、`ObjectStorageNotConfiguredError`、`ObjectNotFoundError`、`ObjectMetadata`、`StoredObject` 和 `ObjectListingPage`。`StoredObject` 承载下载字节、内容类型和元数据；列举结果携带对象摘要、截断标记和下一页 marker。

### 适配器操作范围

- 上传：`put_object(key, data, content_type, metadata)`。
- 下载：`get_object(key, max_bytes=None)`，确保响应资源关闭；提供 `max_bytes` 时超限失败。
- 元数据：`head_object(key)`，对象不存在时提供可区分的异常语义。
- 复制和删除：`copy_object(source_key, target_key)`、`delete_object(key)`。
- 列举：`list_objects(prefix, marker, max_keys)`，返回标准化分页结果，供未来清理任务使用。
- 所有操作统一应用配置中的根前缀。对象键限定在该前缀下；不在基础设施层推断用户身份或进行业务授权。

**关键流程：** `未来业务 Service -> AliyunOSSObjectStorage -> oss2.Bucket -> 私有 OSS Bucket`

采用单一 OSS 适配器，而不是提前引入多云抽象或完整 repository 层：目前确认只有阿里云 OSS，且没有调用方。稳定异常和返回类型独立于 SDK，避免业务层直接依赖 `oss2` 类型。SDK 操作保持同步；将来从异步流程调用时由调用方按项目需要使用线程卸载，适配器不依赖 FastAPI 或 asyncio。

## 12. 风险、假设与运行考虑

- **非阻塞假设：** OSS SDK 版本按 NexusAI 当前 `requirements.txt` 中的 `oss2==2.19.1` 作为移植基线；最终实现时可在依赖锁定审查中调整。
- **主要风险及应对：** 通用对象适配器不执行用户授权或文件格式校验；未来调用方必须负责对象归属、输入校验和业务大小限制。根前缀只提供键空间隔离，不等同于访问控制。
- **安全 / 隐私 / 性能 / 可观测性：** AccessKey 使用 `SecretStr`；endpoint 强制 HTTPS；Bucket 保持私有；日志只记录操作名、Bucket 和错误类型等非敏感上下文；下载支持调用方传入最大字节数。未来异步 Service 应避免直接阻塞事件循环。
- **发布、迁移或回滚：** 无数据库迁移。本次实现不实例化适配器，回滚可移除新增包、配置项和 SDK 依赖；`.env.example` 不存放密钥。
