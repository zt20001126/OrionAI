# 数字人 A 股 K 线查询实现方案

> 日期：2026-11-10  
> 状态：已实现；真实模型及周／月K人工验证待执行  
> 需求确认：已澄清

## 1. 目标与背景

- **要解决的问题：** 数字人目前可以查询单只 A 股最新报价，但不能查看历史价格走势。
- **功能目标：** 使用项目已有 AKShare 依赖，查询单只沪深京 A 股的日 K、周 K 或月 K 数据。
- **预期最终效果：** 用户按股票名称或代码查询时，数字人返回走势摘要，并在数字人对话中显示蜡烛图；未指定周期时使用日 K，未指定区间时显示最近 60 根K线，价格采用前复权。

## 2. 已确认需求

- **使用者 / 调用方：** OrionAI 数字人助手当前用户。
- **触发方式：** 用户询问某只 A 股的历史走势、K线或指定周期行情。
- **输入：** 股票名称或代码；周期日／周／月；可选开始和结束日期。
- **输出：** 依据行情数据生成的简明文字摘要和K线图；文本继续通过 `text_delta` 流式发送，K线图作为一条完整 `MESSAGE` 事件发送。事件和历史消息均采用 `{ "type": "kline_chart", "content": { ... } }` 结构，明确标出股票、周期、区间、前复权口径及数据来源。不得把历史K线描述为实时行情或生成投资建议。
- **主流程：**
  1. 数字人缺股票标识时使用已有 Text 题卡询问；缺周期时默认日 K。
  2. 工具解析股票并查询 AKShare 历史行情；用户指定日期时按该区间查询，否则取最近 60 根有效K线。
  3. 工具检查数据并返回精简 OHLC、日期和摘要所需字段；没有数据或上游失败时返回可区分的状态，不生成图表。
  4. 数字人根据工具结果撰写走势摘要；对话服务持久化最终消息，并在该轮结束前发送一条完整 `kline_chart` MESSAGE 事件。前端收到后立即绘图，历史消息重载时使用持久化的同结构内容绘图。
- **业务规则与边界：** 第一版只支持沪深京 A 股；周期限制为日／周／月；默认前复权 `qfq`，摘要和图表均标明该口径。用户提供区间时校验日期格式、先后关系和合理跨度；K线数量设置上限，避免超大响应。模糊股票名称返回候选供用户确认。
- **异常行为：** 无匹配、多个候选、区间无数据、缺少或无效 OHLC、超时、AKShare 网络／数据异常分别如实反馈；不以查询日期替代行情数据日期，不基于缺少K线断言停牌。
- **权限与数据范围：** 不访问用户私有业务数据；行情是公开第三方数据。会话访问和会员校验沿用现有会话流程。
- **约束：** 仅用于内部功能验证；AKShare 上游数据的使用、展示授权仍须确认。该库已在 `backend/pyproject.toml` 固定为 1.20.27，无需新增依赖。

## 3. 范围

- **本次包含：** 数字人工具、能力提示、结构化 Agent 响应与消息内容、K线图 `MESSAGE` 流式事件及前端即时展示、工具及图表回归测试。
- **本次不包含：** 港股／美股、分钟线、复权方式选择、交易或投资建议、技术指标、行情缓存、独立行情 API、行情持久化表、导出和外部行情主动推送。

当前成功回答由 `DigitalHumanRuntime._response_from_result` 映射成 `AgentResponse`；会话流生成器收到最终结果后调用 `_save_stream_response` 持久化回答。文本增量作为 `text_delta` MESSAGE 发送，题卡在保存后作为 `question` MESSAGE 发送。K线图沿用同一外层 MESSAGE 事件，发送完整 `kline_chart` payload，并把同一 payload 保存为消息 part；前端新增解析回调和本轮状态。图表用结构化 OHLC 在前端本地绘制，不复用只面向生图任务的图片存储接口。

AKShare 官方仓库示例展示 `stock_zh_a_hist(symbol, period, start_date, end_date, adjust)`，period 支持日／周／月粒度，并返回日期、开高低收、成交量等历史字段；官方数据说明同时提示历史行情数据可能存在异常。因此实现需校验返回行及OHLC关系，而不能仅信任列存在。[AKShare 官方代码仓库](https://github.com/akfamily/akshare)，[AKShare 官方数据说明](https://github.com/akfamily/akshare/blob/main/docs/data_tips.md)

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| 数字人 `stock_kline` 工具（新） | 校验输入、复用现有股票匹配、请求历史数据、规范化并裁剪结果 | 数字人 Agent 工具依赖 AKShare；不新增 Router、Service 或 Repository。 |
| 数字人 `graph.py`、`capabilities.py` | 注册工具并提供工具调用规则 | 保持现有 Agent 图和能力注册模式。 |
| Agent Runtime / schema 与会话消息 schema/service | 将本轮图表数据安全地转成消息 part 并持久化；保存成功后发出完整图表 MESSAGE 事件 | 结构化、仅保存最近 60 根或用户区间上限范围内数据；不新增关系表或外层 SSE 事件类型。 |
| 数字人前端页面和会话组件 | 解析完整图表 MESSAGE 事件、持有当前 run 的图表状态；按 OHLC 绘制 SVG 蜡烛图 | 复用现有消息渲染位置和全局设计令牌，不引入图表依赖。 |

### 关键流程

```text
用户问题 -> DigitalHumanRuntime -> get_stock_kline -> AKShare stock_zh_a_hist
                                  -> ToolMessage (摘要字段 + 有界 OHLC 序列)
                                  -> AgentResponse.kline_data
                                  -> 保存 MessageContent.kline_chart part
                                  -> SSE MESSAGE {type: "kline_chart", content: payload}
                                  -> DigitalHumanConversation SVG 蜡烛图 + 文字摘要
```

把数据查询放在独立工具中，避免把外部 I/O 塞入 Router 或前端；K线图使用 OHLC 结构化数据在前端绘制，避免将股票图误作为生图任务、扩展对象存储流程或把大型图片塞入模型提示词。同步 AKShare 调用沿用 `asyncio.to_thread`、超时和有界并发模式；超时并不取消底层线程，应在K线工具中限制并发与响应行数。复用股票匹配前应将现有匹配逻辑提取为有明确契约的共享函数，避免复制匹配规则。

## 9. 接口与数据库变更审查

### 接口影响

| 接口（方法 + 路径 / 事件） | 操作 | 当前定义位置 | 变更前后契约 | 复用判断与变更理由 | 兼容性 / 调用方影响 |
|---|---|---|---|---|---|
| `POST /conversations/{conversation_id}/runs/messages` | 保持不变 | `backend/app/modules/conversations/router/router.py` | 请求不变；完成态消息 `content.parts` 可新增 `type: kline_chart` 的结构化图表部分 | 会话问题与结果已由该接口及运行监听流程承载；不需要单独K线 API。 | API 路径和请求兼容；前端类型需识别新的消息 part，旧消息仍可读取。 |
| `GET /conversations/{conversation_id}/runs/{run_id}/listen` | 保持不变 | `backend/app/modules/conversations/router/router.py` | SSE外层事件种类不变；完成消息按顺序发送文本 `text_delta`，然后在持久化成功后发送完整的 `kline_chart` MESSAGE payload | 复用既有消息事件和运行存储，不增加外层 SSE 类型。 | 前端解析并显示图表；旧客户端忽略不认识的 MESSAGE 内部类型。 |
| SSE `event_type=message`, `data.type=kline_chart` | 新增 MESSAGE payload 类型 | `backend/app/modules/conversations/schemas/schemas.py`、`service.py` | 新增 `content` 对象，包含 `code`、`name`、`period`、`adjust`、日期范围及 `candles` OHLC 数组；仅在最终消息持久化成功后发送 | 复用既有 SSE MESSAGE 外层及运行存储，不增加外层事件枚举或新端点；这是已确认的流式图表需求。 | 老客户端可忽略未知 payload；新客户端收到完整数据后绘图。 |
| `GET /conversations/{conversation_id}/messages` | 保持不变 | `backend/app/modules/conversations/router/router.py` | 响应中消息 parts 可包含 `kline_chart` | 历史消息由现有查询接口返回，无需新端点。 | 现有历史渲染须处理新 part。 |

### 数据库影响

| 表 / 字段 | 操作 | 当前定义位置 | 用途与需求依据 | 复用判断与新增理由 | 迁移 / 回填 / 默认值 / 回滚 |
|---|---|---|---|---|---|
| `messages.content` JSON | 保持表结构不变；JSON parts 增加可选 `kline_chart` 类型 | `backend/app/modules/conversations/models/models.py` 的 `Message.content`；校验见 `conversations/schemas/schemas.py` | 持久化数字人返回的图表OHLC数据，以便历史会话仍可展示 | 现有内容结构就是多态消息部分的存储载体；新增列或独立行情表不能提升此场景能力。 | 无迁移、回填或默认值；旧记录保持原样。应用回滚后旧前端忽略或无法绘制该 part，需回滚前确认新消息不再被旧版本读取。 |

### 最小变更结论

- **可复用的现有接口 / 数据结构：** 会话发消息、SSE `MESSAGE` 外层、历史消息读取；消息 `content.parts` JSON；数字人图工具注册；A股股票代码列表和名称匹配；前端数字人消息组件。
- **本方案实际新增或修改的最小集合：** 一个K线查询工具、完成态及消息 part 增量、`message` payload `kline_chart`、数字人图注册／提示、当前轮流式图表状态、SVG绘图组件及针对性测试。
- **排除的冗余设计及原因：** 不新增 API、数据库列、行情缓存、对象存储流程、图表库或分钟线；这些都不是已确认需求的必要条件。
- **尚未确认的接口或数据决策：** 无。AKShare 上游可用性及行情展示许可仍是实施验证和发布前风险，不改变本方案契约。

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 支持用户可选开始／结束日期；只给开始日期时结束日期使用当前上海时区日期，只给结束日期时按周期回看相应查询窗口；未给周期默认日 K。单次查询最多 300 根K线。
- **主要风险及应对：** AKShare 第三方网页源可变且有运行历史行情异常记录；固定当前已装版本、测试必要字段和OHLC逻辑，真实上游验证失败时停止功能发布。前复权数据会随公司行为或上游调整变化，图表明确标注口径。图表数据写入消息 JSON 会增加消息体积，严格限制为默认 60 根或经约束区间上限。
- **安全 / 隐私 / 性能 / 可观测性：** 日期和周期在工具边界校验；对同步网络请求线程化，等待超时不代表取消请求，使用有界并发保护进程资源；不记录完整外部数据和用户消息。
- **发布、迁移或回滚：** 无数据库迁移和额外环境变量。前后端需协同部署以渲染新增消息 part；回滚时对旧版本读取新 JSON part 的行为做检查。
