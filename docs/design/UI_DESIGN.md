# OrionAI 前端 UI 设计规范

本文记录 OrionAI 当前前端的设计基准，供新页面和页面改动复用。规范以现有登录注册页、技能市场页及其样式代码为依据；需要新增样式时优先沿用已有主题变量和组件。当前主要样式来源为 `frontend/src/styles/global.css` 与 `frontend/src/features/platform/platform.css`。

## 1. 设计原则

- 采用 OrionAI Light Design System：企业级浅色界面、科技蓝品牌色、极浅蓝灰页面底色、白色内容面、柔和边框和克制阴影。
- 先保证层级清晰、信息易读和操作明确，再使用渐变、插画或动效作辅助。
- 登录注册页与技能市场页是视觉基准。页面结构可按业务调整，但颜色、排版、控件、状态和动效应保持同一语言。
- 优先使用全局 CSS 变量、现有页面壳层和现有图标/品牌组件。不要新增无必要的依赖、全局导航或一套平行视觉体系。
- 保留页面已有业务状态、路由、表单提交和交互行为；样式调整不得隐式改变这些行为。
- 颜色、尺寸和断点以代码中的值为准。新增通用设计值时，先检查全局变量能否表达；确有缺项时，以语义变量最小补充并复用。

当前可复用入口包括全局 `.button` 样式、认证模块的 `BrandMark`、平台模块的 `PlatformIcon` 与 `PlatformLayout`；`SkillCard`、技能详情弹窗等属于平台功能组件。优先复用这些实现及样式，避免在新页面复制后分叉。

## 3. 字体与排版层级

- 全局字体栈为 `Inter`, `Segoe UI`, `Microsoft YaHei`, `sans-serif`；基础字号 `14px`，字重 `400`。中文优先由系统中文字体回退显示，不另载入新字体。
- 使用深色标题与灰蓝辅助文字形成层级。标题常使用较重字重和轻微负字距；正文保留舒适行高。
- 当前主要字号以页面实现为准：认证主标题 `25px`（窄屏 `23px`）；市场 Hero 标题 `clamp(26px, 2.5vw, 34px)`（移动端 `25px`）；市场分区标题 `18px`（窄屏 `16px`）；技能卡片标题 `14px`；辅助说明多为 `9–13px`。
- 新内容沿用页面既有层级和对应组件字号，不为单个页面另建字号体系。长说明使用正文层级，不用小号文字承担主要信息。

## 4. 页面布局与间距

全局间距基准为 `--space-1` 至 `--space-8`：`4px`、`8px`、`12px`、`16px`、`20px`、`24px`、`32px`。一般控件间距优先从此尺度选择。布局中已有的 `clamp()`、内容宽度、卡片内边距和断点规则属于页面结构参数，应按当前实现复用，避免为贴合尺度而造成视觉变化。

### 认证页

- 桌面采用产品介绍与认证卡片并列的两栏布局，列比例为 `1.18fr / 0.82fr`，认证列最小宽度 `420px`。
- 认证卡片最大宽度 `458px`，内边距随视口在 `30px` 至 `42px` 间调整，白底、细边框、`--radius-panel` 圆角和轻柔卡片阴影。
- `1100px` 以下调整列比例和展示内容；`820px` 以下隐藏产品介绍区、认证卡片居中；`480px`、`360px` 以下继续收紧内边距及验证码表单布局。

### 平台与技能市场

- 桌面平台壳层为左侧导航和右侧内容区，初始侧栏宽 `252px`；顶部栏固定吸附视口上缘，当前高度 `68px`。
- 主内容区最大宽度 `1400px`，左右内边距按视口在 `22px` 至 `45px` 间变化。技能市场采用清晰的纵向分区、宽松区块间距和卡片网格。
- `1120px` 以下侧栏收至 `226px`、技能卡网格变为两列；`800px` 以下导航转为顶部横向滚动导航；`560px` 以下卡片改为单列并进一步压缩页面间距。
- 在保留业务需要的情况下可使用不同内容布局；认证与平台导航的全局骨架、层级和响应式行为不得被页面私自改写。

## 5. 导航栏与顶部栏

- 平台桌面导航位于白色固定侧栏，品牌标记与名称置顶，导航项纵向排列，工作空间和账户入口位于底部。
- 当前导航项使用品牌文字色、`--color-platform-active-soft` 浅蓝底和左侧品牌色指示条；Hover 使用 `--color-platform-interaction-soft`。窄屏横向导航通过底部指示线标记当前项。
- 顶部栏提供面包屑式页面上下文、通知和用户入口。使用轻边线、半透明白底和轻度背景模糊；移动端降低高度与内边距。
- 不新增、移除或重排全局导航入口，不擅自改变桌面侧栏与移动端横向导航的切换方式。

## 6. 按钮、表单、卡片与弹窗

### 按钮

- 通用按钮样式为全局 `.button`。主要操作使用品牌实色和轻阴影；次要操作使用白底、浅边框；描边按钮 Hover 转为浅蓝底和品牌色文字。
- 控件高度以当前 `46px` 至 `49px` 为主，验证码按钮和弹窗按钮按其现有布局缩小。按钮文字保持简洁，图标与文字间距适中。
- 加载态在原按钮内显示旋转指示器，避免操作中布局跳动。

### 表单

- 认证输入框当前最小高度 `47px`、圆角 `--radius-control`，使用白底、强边框和浅灰蓝占位文字；标签置于输入框上方。
- 聚焦时用品牌色边框和焦点环；错误时用错误色边框及浅红焦点底；禁用时降低文字对比、使用禁用底色并显示不可用指针。
- 搜索框沿用白色容器和圆角边框，聚焦时由容器的 `:focus-within` 显示品牌色焦点环。
- 认证页提供登录、注册和密码重置视图；邮箱验证码有请求中与冷却状态，密码字段可切换可见性，提交中有加载反馈，并通过文字消息呈现成功或错误。改样式时保留表单状态、校验和提交流程。
- 技能市场搜索框与分类选项共同筛选技能；技能卡片打开详情弹窗，用户菜单提供个人设置和退出入口。视觉调整应保留筛选、弹窗关闭及账户操作行为。

### 卡片

- 认证卡、技能卡和市场 Hero 都采用浅色页面上的白色或近白色表面、细边框和柔和阴影。
- 技能卡当前圆角 `16px`，Hover 轻微上移 `3px` 并增强阴影；卡片内的品类图标以低饱和的蓝、绿、紫、橙色区分语义。
- 卡片间距与内边距按页面网格选择；复用既有卡片类型时不得另造一套边框、阴影或圆角风格。

### 弹窗与浮层

- 技能详情弹窗使用居中白色面板、暗化并轻度模糊的遮罩、细边框和柔和深阴影；当前面板最大宽度 `470px`，桌面内边距 `29px`。
- 用户菜单作为锚定浮层呈现，保持较轻阴影和紧凑菜单项。新弹窗/菜单应支持清晰关闭入口、键盘聚焦样式和 Escape 关闭，并为对话框提供正确的可访问名称与语义。
- 保持现有技能详情弹窗通过 Escape、遮罩点击和关闭按钮关闭的行为；不在视觉改动中改变其业务交互。

## 7. 图标使用规范

- 优先复用 `PlatformIcon`、`BrandMark` 和现有 SVG 插画，不为已有含义重复绘制图标或引入图标字体/图标框架。
- 平台线性图标使用描边、圆角端点与圆角连接，当前 `stroke-width` 为 `1.65`，颜色继承 `currentColor`；尺寸由组件 `size` 属性控制，默认 `20px`。
- 图标应与文字基线和控件尺寸协调。装饰图标设置为辅助技术隐藏；独立操作图标按钮应有可访问名称。

## 8. Hover、Focus、Active、Disabled 状态

- **Hover：** 可点击元素通过品牌色、柔和浅蓝底、边框或轻微阴影反馈；避免大幅移动和强烈颜色闪变。
- **Focus：** 键盘操作必须有可见焦点状态。按钮、导航、菜单、分类选项和关闭按钮使用品牌色轮廓；表单使用品牌边框/焦点环。不要用全局 `outline: none` 后遗漏替代状态。
- **Active：** 按钮和导航只作轻微按压反馈；当前导航、选中分类等持久状态除颜色外应有明确选中语义（如 `aria-current`、`aria-pressed`）。
- **Disabled：** 保留可读标签、降低视觉强调并显示不可用指针；禁用操作不能继续触发业务动作。
- **错误/成功：** 使用既有 danger/success 文字、浅底与边线变量，配合文字说明，不只依赖颜色传达状态。

## 9. 动画与过渡效果

- 全局快速与常规过渡分别为 `--motion-fast: 160ms ease`、`--motion-normal: 220ms ease`。颜色、边框、阴影和小幅位移优先使用这些变量。
- 当前页面使用短促的内容淡入上移、卡片轻抬、菜单弹出和弹窗淡入；菜单约 `120ms`、详情弹窗约 `170ms`。加载旋转使用 `800ms linear`。
- 动效应帮助确认交互，不延迟操作。必须保留 `prefers-reduced-motion: reduce` 支持：全局缩短动画与过渡，平台卡片和浮层移除动画与过渡。

## 10. 响应式设计

- 以内容可读、控件可操作为目标，优先调整列数、导航方向、隐藏非必要装饰内容及内边距，不压缩文字到难以辨读。
- 当前认证页断点为 `1100px`、`820px`、`480px`、`360px`；平台和市场页断点为 `1120px`、`800px`、`560px`。这些断点对应既有页面结构，不应在单个新页面中复制粘贴另一套全局断点行为。
- 保证页面至少适配 `320px` 宽度（全局 `html`、`body` 已设置最小宽度），横向溢出的导航应可滚动，表单和卡片内容不得被裁切。
- 使用 `100svh` 适配移动端视口高度时，保留项目当前 `100vh` 回退写法。

## 11. 页面一致性检查标准

新建或修改页面后逐项检查：

1. 已阅读本规范，且登录注册页/技能市场页仍作为视觉基准。
2. 使用现有字体、品牌色、状态色、间距、圆角、阴影和动效变量；新增变量有明确语义且未复制已有变量。
3. 页面结构符合认证布局或平台布局的导航、顶部栏、内容宽度与响应式规则；若业务需要不同布局，视觉语言仍一致。
4. 按钮、表单、卡片、菜单和弹窗的尺寸、表面、边界、交互状态与既有组件一致。
5. 图标线条风格统一；独立操作有可访问名称，选中项有语义标记，键盘焦点清晰。
6. Hover、Focus、Active、Disabled、错误、成功和加载状态都有明确反馈；减少动态效果偏好得到尊重。
7. 在桌面、平板和窄屏下检查布局，无意外横向溢出或控件遮挡。
8. 样式修改没有移除或改变原有业务逻辑、表单、路由、会话和菜单交互。
9. 突破本规范前，先说明需求、影响范围与理由并请求确认。
