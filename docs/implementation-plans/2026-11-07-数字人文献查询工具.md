# 数字人文献查询工具实现方案

> 日期：2026-11-07  
> 状态：待审阅  
> 需求确认：已澄清；数量上限等非阻塞假设见下文

## 目标与需求

数字人通过现有对话，根据关键词查询 OpenAlex 文献。关键词必填，缺失时使用现有自由输入题卡询问；年份支持单年或闭区间，未指定时使用北京时间当前自然年；数量未指定时为 5。用户明确指定的年份或数量不能被静默替换，年份范围倒置或数量无效时请用户修正。默认年份无结果时如实说明，不自动扩展年份。

保留 OpenAlex 所有文献类型，并展示类型。每条结果只包含标题、作者、发表年份和日期、期刊或来源、DOI、被引用次数、摘要、文献类型、OpenAlex 链接；查询级信息包括实际关键词、年份范围、请求数量、匹配总数及返回数量。结果不足、无结果、字段缺失和查询失败均如实报告，不能编造文献及摘要。

非阻塞设计假设：首版数量为 1–100 条（OpenAlex 每页上限 100），超过时询问用户调整；关键词去除首尾空白后不得为空且最多 200 字符；年份为正整数且不早于 1000，不限制未来年份以允许预出版数据。用户主动指定年份范围时两端均包含；不默认限定语言、不额外引入多轮扩词。文献以 OpenAlex 默认相关性排序。100 条完整摘要可能超出模型上下文或输出限制，实施时应测试并记录实际限制，不宣称一定能完整呈现；如现有模型无法满足须调整方案并取得用户决定，不得静默截断。

## 已核实的现状

- `backend/app/modules/digital_human/agent/graph.py` 在 `create_digital_human_graph` 中注册工具；`capabilities.py` 根据注册工具生成能力与调用规则。`prompts/loader.py` 组合提示词。
- `backend/app/modules/digital_human/agent/tools/news.py` 已使用 `httpx.AsyncClient`、配置及工具结果处理外部检索；`backend/tests/unit/test_digital_human_news.py` 使用 MockTransport 和脚本模型测试工具链。
- `backend/app/agent/tools/builtin/ask_user_questions.py` 支持自由输入题卡；数字人已有检查点与恢复路径。`frontend/src/features/digital-human/components/DigitalHumanConversation.tsx` 已渲染 Markdown 和题卡。
- `backend/app/core/config.py` 的 `Settings` 从根目录 `.env` 加载配置，密钥采用 `SecretStr`；`docker-compose.yml` 的 backend 环境变量需显式传递，`.env.example` 和 `docs/development/local-setup.md` 记录配置。
- `backend/pyproject.toml` 已依赖 httpx、Pydantic、pytest 和 Ruff，无需新增依赖。
- OpenAlex `/works` 真实请求已验证可返回中文结果。字段以 [文献属性](https://help.openalex.org/data/works/attributes/)、[筛选](https://help.openalex.org/api/filtering/) 和 [分页限制](https://help.openalex.org/api/authentication/) 为准；摘要为倒排索引且可能为空，作者和来源等字段也可能缺失。

## 设计与数据流

```text
用户对话 → 数字人模型 → 缺关键词：ask_user_questions → 恢复对话
                    → 参数齐全：search_literature → OpenAlex /works
                                               → 校验、摘要还原、字段映射
                                               → 工具结构化结果 → 模型组织回答
```

复用新闻工具的同模块模式：在数字人工具文件内完成单一外部 API 的异步请求和转换，避免无实际复用需求的新 Service、Repository 或 Provider 层。模型负责识别意图与组织回答；工具负责输入边界、默认值、请求、字段转换和错误区分。默认年份在工具内按 `Asia/Shanghai` 计算，以免依赖模型猜测；能力提示明确不要自行猜测或改写年份。未指定数量时工具默认 5。

### 工具契约

拟新增 `search_literature(keyword: str, start_year: int | None = None, end_year: int | None = None, count: int = 5)`。两个年份均为空表示当前自然年；只传一个年份表示单年；两个均有值表示闭区间。明确校验空关键词、年份与顺序、数量范围。仅在工具成功时返回成功状态，包含查询条件、`meta.count` 与标准化文献数组；空结果是成功且列表为空；错误返回可辨认的失败状态和面向用户的提示，不能以空列表掩盖失败。

请求 `GET https://api.openalex.org/works`：`api_key` 来自服务端配置；`search=keyword`；单年使用 `filter=publication_year:YYYY`，范围使用 `filter=from_publication_date:YYYY-01-01,to_publication_date:YYYY-12-31`；`per_page=count`。以 `select` 仅选择以下字段：

| 展示字段 | OpenAlex 字段 | 缺失处理 |
| --- | --- | --- |
| 标题 | `display_name` | 缺失或空标题表示上游数据无效，报告错误 |
| 作者 | `authorships[].author.display_name` | 空列表显示暂无作者；保留上游顺序 |
| 年份、日期 | `publication_year`、`publication_date` | 未提供时显示暂无 |
| 期刊或来源 | `primary_location.source.display_name` | 允许 location 或 source 为空，显示暂无 |
| DOI | `doi` | 空值显示暂无 |
| 引用次数 | `cited_by_count` | 空值显示暂无，不能当作 0 |
| 摘要 | `abstract_inverted_index` | 空值显示暂无；按词语位置还原原文，位置无效时报告上游数据异常 |
| 文献类型 | `type` | 缺失显示暂无，保留上游类型 |
| OpenAlex 链接 | `id` | 缺失或格式无效时报告上游数据异常 |

保留原文语言；摘要为第三方内容，不应当作指令执行。DOI 和 OpenAlex 地址保留为链接，利用现有 Markdown 展示；结果只包含请求字段，不新增开放获取或 PDF 字段。模型要保留原文和链接，明确摘要缺失，不能推断作者或来源。列表接口的作者可能不完整（OpenAlex 列表最多返回前 100 位），不能声称覆盖所有作者。

### 失败、超时与配置

按用户提出的配置新增 `OPENALEX_API_KEY`、`OPENALEX_TIMEOUT_SECONDS=20`、`OPENALEX_MAX_RETRIES=2`、`OPENALEX_RETRY_DELAY_SECONDS=0.5`，分别配置密钥、每次请求超时、初次请求后的最大重试数和基础等待时间。对连接/超时和 429、502、503、504 做有界重试；429 优先遵循可解析的 `Retry-After`，且设置等待上限避免请求长时间占用；其他失败不盲目重试。无密钥时明确提示管理员配置，不请求上游；401/403、限流、超时/网络、其他 HTTP 错误和无效 JSON/字段分别给出可理解的失败结果。重试耗尽后不得返回假成功。

使用官方要求的查询参数传密钥；不记录完整 URL、异常原文、密钥或未经必要脱敏的请求数据。`RESEARCH_MAX_SEARCH_ROUNDS` 暂不接入：本需求每次只执行一次检索及必要网络重试，并无多轮搜索规则；若以后需要多轮检索，再单独设计，避免引入无效配置。密钥仅写入未提交的环境配置，示例文件留空。

## 接口与数据库影响

不新增或修改对外 API、SSE 事件或数据表。复用 `backend/app/modules/conversations/router/router.py` 已有、认证及会员约束不变的以下接口：

| 方法与路径 | 操作 | 作用 |
| --- | --- | --- |
| `POST /api/conversations/{conversation_id}/runs/messages` | 不变 | 提交用户消息并启动运行 |
| `POST /api/conversations/{conversation_id}/runs/answers` | 不变 | 题卡答案恢复运行 |
| `GET /api/conversations/{conversation_id}/runs/{run_id}/listen` | 不变 | 接收现有 SSE 文本及题卡事件 |
| `POST /api/conversations/{conversation_id}/messages`、`/messages/stream`、`/answers`、`/answers/stream` | 不变 | 保留现有同步和流式对话契约 |

`backend/app/modules/conversations/models/models.py` 的 `conversations` 和 `messages.content` 保持不变：助手回答沿用既有消息保存；工具中间结果的保留遵循现有 LangGraph Checkpointer 策略。无独立文献表、字段、索引、迁移或回填；不承诺把结构化检索结果作为独立记录永久保存。

## 实施步骤与验收

1. **配置与工具**：修改 `config.py`、新增 `literature.py`，按上述契约调用上游并转换结果。验收：单年、范围、默认值、查询数量和所需字段正确；摘要顺序正确；无结果、缺失字段、错误状态可区分；密钥不出现在日志或结果中。使用 MockTransport 验证参数、响应及重试。
2. **接入数字人**：修改 `graph.py`、`capabilities.py`。验收：注册能力出现在可用清单；缺关键词触发题卡并可恢复；用户指定范围和数量被保留，省略时按工具默认值执行；模型仅依据工具结果回答。使用脚本模型覆盖调用和恢复，并以真实模型人工验证，识别模型行为的不确定性。
3. **运行配置和文档**：修改 `.env.example`、`docker-compose.yml`、`docs/development/local-setup.md`、`docs/architecture/overview.md`。验收：宿主机和 Compose 均能读到对应配置，空密钥不影响应用启动但查询会明确失败，文档不包含真实密钥。
4. **验证与回归**：新增 `backend/tests/unit/test_digital_human_literature.py`，覆盖查询参数、数量边界、年份边界、中文关键词、摘要重排、缺失可选字段、无结果、无密钥、429/超时/网络/无效响应和有界重试；覆盖图调用与题卡恢复。运行相关 pytest、既有数字人 Agent 回归和 Ruff；在可用环境执行一次真实上游与真实模型端到端验证，包括历史消息、链接和默认年份。测试结果实施后据实记录。

## 风险与交付边界

- 文献数据是上游索引，不保证覆盖完整、分类或语言始终准确；相关性检索可能出现同名或不相关记录。显示匹配总数，不将其称为高质量论文数。
- 一次返回较多篇且含完整摘要可能超过上下文、响应或语音播放的合理长度；先测试现有链路。若无法完整展示，应另行讨论结构化渲染或合理的数量限制。
- OpenAlex 的额度、费用、限流与可用性可能变化；遵循响应中的限流信息，部署前核实账号额度。
- 本方案仅用于审阅，尚未实施代码，也未执行上述自动化或端到端验证。部署通过环境变量启用；回滚代码及配置即可，无数据迁移。
