# 会话自动命名实现方案

> 日期：2026-10-27（Asia/Shanghai）
> 状态：待审阅
> 需求确认：已澄清；历史会话处理为非阻塞假设

## 1. 目标与背景

- **要解决的问题：** OrionAI 已有会话标题字段和历史会话展示，但新会话标题一直为空，列表只能显示“未命名会话”及创建时间。
- **功能目标：** 首条用户消息进入已有会话 API 后，根据其主要意图自动生成简短标题并保存。
- **预期最终效果：** 首轮回复完成后，会话列表显示模型生成的标题；模型不可用时显示首条消息的简短摘要。后续轮次不更改标题。

## 2. 已确认需求

- **使用者 / 调用方：** 登录用户；触发方为现有聊天页面，执行方为 conversations Service。
- **触发方式：** 对一个尚无消息的空会话首次调用 POST /api/conversations/{id}/messages。
- **输入：** 首条用户文本；标题模型输入截取前 4,000 个字符。
- **输出：** 写入现有 conversations.title 字段；响应 DTO 和 JSON 结构不变。
- **主流程：**
  1. Service 在当前用户的会话范围内判断该会话是否还没有消息。
  2. 持久化首条用户消息，并启动标题生成与现有 Agent 调用并行执行。
  3. 标题生成器按提示词约束模型输出同语言、最多 15 个字符的标题，清理格式后返回。
  4. Service 在首轮 API 返回前保存标题；列表 API 随后返回该标题，现有历史组件显示它。
- **业务规则与边界：**
  - 只从会话的第一条用户消息命名；单个会话只写入一次。
  - 仅使用现有 DeepSeek Provider，不新增模型供应商或第三方依赖。
  - 模型输出只保留第一条非空行，去除引号及“标题：”前缀，限制为 15 个字符。
  - 模型失败、超时或输出无效时，压缩首条消息中的空白并截取前 15 个字符；空内容回退为“新会话”。
  - 不提供手动重命名功能。
- **异常行为：** 标题模型失败不能使消息/Agent 请求失败；标题任务有独立超时，错误只记录必要的错误类型或会话标识，不记录首条消息原文。
- **权限与数据范围：** 复用现有 Service 的会话所有权检查；标题写入按会话 ID 且仅在标题为空时更新。
- **约束：** 沿用 Router → Service → Repository、core lifespan 依赖注入、现有 conversations.title 和前端历史列表；不改导航、页面布局或聊天 API 契约。

## 3. 范围

- **本次包含：** 标题提示词与生成/规范化逻辑、首轮检测和并行编排、失败回退、条件写入、超时配置、测试和 API/架构/数据库文档更新。
- **本次不包含：** 手动改名 API 或 UI、对既有历史消息批量调用模型回填标题、修改会话/消息表结构、流式返回标题事件。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| modules/conversations/title.py（新增） | 接收注入的 BaseChatModel，生成标题、规范化模型输出，并提供首条消息回退函数 | 不读取环境变量、不访问 ORM；模型由 core 组合层注入 |
| agent/prompts/templates/conversation_title.md（新增）及 agent/prompts/loader.py | 存放并加载标题专用提示词 | 沿用现有本地模板；与通用 Agent 系统提示词分开 |
| modules/conversations/service.py | 仅在首条消息触发标题任务；将标题任务与 Agent 异步调用并行；在成功、失败或等待题卡时均完成标题保存 | 保留会话权限与消息业务的现有所有者；标题失败不能覆盖 Agent 结果 |
| modules/conversations/repository.py | 检查历史消息并使用空标题条件更新 | 仅处理 SQLAlchemy 查询，不承载模型逻辑 |
| core/application.py、modules/conversations/dependencies.py | 在 lifespan 构造并注入 Title Generator | core 负责组装；Service 不直接构造 Provider 或读取配置 |
| 前端历史列表 | 继续读取 title 并展示 | 当前已有显示和发送后刷新行为；仅增加回归测试 |

### 关键流程

~~~text
ConversationPage 首次发送
  -> POST /api/conversations（现有：创建空会话）
  -> POST /api/conversations/{id}/messages（现有）
  -> ConversationService 校验所有权并判断无历史消息
  -> 保存首条用户消息
  -> 标题生成任务 || BaseAgent.ainvoke（经现有 AnyIO 线程桥）
  -> 标题模型结果 / 首条消息回退
  -> Repository 条件写入 conversations.title
  -> API 返回现有 AgentTurnResponse
  -> ConversationPage 递增 historyRefreshKey
  -> GET /api/conversations，历史列表展示标题
~~~

首条消息判定须在提交用户消息前完成。为避免两个并发首发请求都将自己当成首条消息，Service 对该会话的“检查是否为空 + 保存用户消息”使用会话行锁；锁在用户消息提交后释放，不跨越模型调用。标题结果最终通过 title IS NULL OR title = '' 条件更新，防止重复任务覆盖已有标题。

Service 是同步 FastAPI 路由调用的同步编排层，Agent 则通过 AnyIO 调用异步图。方案在 Service 内通过 AnyIO 当前 worker 对应的事件循环启动一个标题协程，并让它与 Agent 协程并行；两者结果在 API 返回前收束。标题协程使用 asyncio.timeout，超时结果按模型不可用处理。这样前端现有的发送后列表刷新能读到最终标题，也不把标题生成串行附加到 Agent 回复耗时之后。

同一个标题模型使用和 Agent 相同的 Provider、模型配置与脱敏约束；新增配置只控制标题调用时限，默认 8 秒。提示词将用户消息作为待概括内容，不执行消息中的指令。

## 10. 分步实施计划

### 步骤 1：实现标题生成器及运行配置

- **目的：** 建立可测试、可超时、模型失败可回退的标题生成边界。
- **涉及文件：** backend/app/modules/conversations/title.py（新增）、backend/app/agent/prompts/templates/conversation_title.md（新增）、backend/app/agent/prompts/loader.py、backend/app/core/config.py、backend/app/core/application.py、backend/app/modules/conversations/dependencies.py、backend/tests/unit/test_conversation_titles.py（新增）、backend/tests/unit/test_application_lifespan.py。
- **实施内容：** 通过已配置 Provider 构造生成器；加载专用提示词；截断输入、规范输出；使用 Settings 中的 8 秒默认超时（不新增 .env.example 条目）；提供 whitespace-normalized fallback。
- **前置依赖：** 无。
- **验收标准：**
  - [ ] 有效模型结果被清理为首行、最多 15 个字符。
  - [ ] 空结果、异常或超时均可得到 fallback，且生成器异常不泄露消息原文或密钥。
  - [ ] 应用 lifespan 将生成器注入 Service 所需的应用状态，并在退出时清理。
- **验证方式：** 标题模块单元测试、设置边界测试、lifespan 测试。

### 步骤 2：将标题接入首条消息业务流

- **目的：** 首条消息触发一次命名，后续轮次不覆盖标题。
- **涉及文件：** backend/app/modules/conversations/service.py、repository.py、schemas.py、backend/tests/integration/test_conversation_endpoints.py。
- **实施内容：** 在用户消息提交前检查历史消息；针对首次发送短暂锁定会话行并提交用户消息；标题协程与 Agent 调用并行；在流程收束时无论 Agent 正常、等待题卡或失败都保存生成标题或 fallback；Repository 只在标题为空时写入。
- **前置依赖：** 步骤 1。
- **验收标准：**
  - [ ] 新建空会话的首条消息会在 GET /api/conversations 中得到非空标题。
  - [ ] 第二条及后续消息、题卡答案不会触发新的标题生成或覆盖已有标题。
  - [ ] 已有消息但标题为空的会话，在后续发送时保持空标题，不把后续内容冒充首条消息。
  - [ ] 标题模型超时或失败时，用户首条消息仍完成正常聊天，列表标题变为摘要回退值。
  - [ ] 并发首发请求只会由实际首条消息决定标题，已保存的标题不被覆盖。
- **验证方式：** 现有会话 API 集成测试增加注入假生成器的用例；不调用真实模型或外网。

### 步骤 3：锁定现有前端刷新行为

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 仅没有历史消息的会话参与自动命名；功能上线前已有消息且标题为空的会话不批量回填，继续显示前端现有未命名标签。
- **主要风险及应对：** 标题额外调用模型会增加成本；与 Agent 并行且使用独立短超时，生成失败时本地回退，不影响回答。并发首发由会话行锁保护首条判定，落库再加空标题条件。
- **安全 / 隐私 / 性能 / 可观测性：** 标题模型收到首条消息文本，使用现有对话 Provider；日志不记录原始文本或密钥；超时默认 8 秒，可配置；只为每个空会话的首轮调用一次。
- **发布、迁移或回滚：** 无数据库迁移。部署前配置现有 DeepSeek 变量；标题超时使用 Settings 中的 8 秒默认值，不要求新增部署变量或修改 .env.example。回滚应用代码不需恢复数据库结构。
