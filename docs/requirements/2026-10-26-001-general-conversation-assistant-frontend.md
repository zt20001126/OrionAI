# 通用对话助手前端入口与对话页面

## 1. 需求背景

项目已有基础对话智能体的后端能力，但前端没有可供用户使用的入口和对话页面。用户提供的截图作为“我的智能体”页面的目标参考。

## 2. 需求目标

登录用户能够从“我的智能体”进入通用对话助手，发送消息、查看回答、进行多轮对话，并查找、切换和继续自己的历史会话。

## 3. 当前功能现状

- `frontend/src/features/platform/platformData.ts` 已定义“我的智能体”和“会话记录”导航项；`PlaceholderPage.tsx` 中两个页面目前均为“建设中”占位页。`frontend/src/app/App.tsx` 只展示技能市场或占位页。
- `backend/app/modules/conversations/router.py` 已提供登录保护的会话创建、会话列表、消息列表、发送文本和提交题卡答案接口。`schemas.py` 定义完整 JSON 回答与题卡结构；当前没有流式输出。
- 后端会话目前不自动生成标题。仓库代码支持上述能力，但本需求澄清阶段未进行真实服务联调。

## 4. 详细功能需求

1. **我的智能体入口**：将“我的智能体”占位页改为与参考截图风格一致的页面，展示“通用对话助手”卡片。点击卡片进入对话页。截图中的“添加”和“添加更多智能体”保留展示，但须明确标为“暂未开放”，且不能触发添加操作。
2. **对话**：对话页提供消息区域和文本输入。用户可发送非空文本，看到自己的消息、提交中状态及助手返回的完整回答，并在同一会话继续提问。
3. **题卡**：当助手返回单选题卡时，页面展示题目和选项；用户完成当前题卡选择并提交后，继续该会话。待答期间应说明需先完成选择。
4. **历史会话**：用户可在对话页查看、切换并继续自己的历史会话；侧栏“会话记录”入口也可进入历史会话列表并打开其中一条继续对话。没有历史记录时显示清楚的空状态。
5. **页面状态与权限**：加载、提交、失败和服务不可用时显示文字反馈；失败时不自动重复发送消息。只能访问当前登录用户的会话。

## 5. 用户操作流程

用户登录后打开“我的智能体” → 点击“通用对话助手” → 进入空白对话视图并发送文本 → 查看助手回答或完成题卡 → 继续对话。用户也可从对话页或侧栏“会话记录”选择已有会话，查看消息并接着交流。

## 6. 预期实现效果

“我的智能体”成为可用入口；用户能完成新会话、多轮对话、题卡选择，以及历史会话的查找和续聊。页面沿用现有浅色、克制使用品牌蓝的视觉规范。

## 7. 功能边界与约束

本次不包含新增智能体、会话删除或重命名、自动标题、流式输出、文件或图片消息。保留现有导航结构、登录要求及其他页面功能。“添加”相关控件只展示未开放状态。前端页面遵循 `docs/design/UI_DESIGN.md`。

## 8. 异常情况与边界处理

空白消息不能提交；发送中应避免重复提交。会话不存在、无权访问或服务暂不可用时，页面给出可理解的提示，不展示底层错误。历史记录为空时不显示虚构会话。

## 9. 验收标准

- [ ] 登录用户点击“我的智能体”中的“通用对话助手”卡片，可进入对话页。
- [ ] 用户可发送文本、查看完整回答，并在同一会话继续提问。
- [ ] 助手返回题卡时，用户可选择并提交答案，随后继续对话。
- [ ] 用户可从对话页和“会话记录”入口打开自己的历史会话并续聊。
- [ ] 空状态、加载状态及请求失败均有明确反馈。
- [ ] “添加”相关控件明确显示未开放，不能执行添加操作。
- [ ] 页面符合现有 UI 规范，不改变全局导航结构。

## 10. 已确认事项与合理假设

- **已确认**：截图中的卡片页属于本次范围；包含历史会话切换；“会话记录”入口可打开历史会话；“添加”相关控件显示为未开放。
- **合理假设**：点击助手卡片先进入可输入的空白对话视图，用户开始发送消息后形成可续聊的会话；依据是用户要求点击后进入对话页面，且后端会话可以为空。
