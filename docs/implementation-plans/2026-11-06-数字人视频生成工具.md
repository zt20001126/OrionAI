# 数字人视频生成工具实现方案

> 日期：2026-11-06  
> 状态：待审阅

## 目标与范围

数字人根据用户文字描述调用百炼 `wan3.0-video-prime` 生成一个视频，保存到现有私有 OSS，在当前对话和历史消息中播放。沿用数字人现有工具注册与消息刷新方式；图片工具、图片智能体、图片读取接口和图片生成逻辑不修改。

本期假设只做文生视频，一次生成一个 MP4。用户未指定画幅、时长或分辨率时使用模型默认值，不弹题卡；生成前仅在缺少必要画面描述时询问。不引入图生视频、参考素材上传、视频编辑或新的后台任务框架。模型名属于核心配置，使用现有百炼密钥与地址；轮询间隔和请求超时使用代码常量。

## 现有代码与设计

- `backend/app/modules/digital_human/agent/graph.py` 静态注册数字人工具；`agent/tools/generate_image.py` 展示了模块级工具和服务端上下文的用法。
- `backend/app/modules/digital_human/agent/runtime.py` 从本轮工具消息提取图片任务 ID；视频可采用同样的方式填入新增的 `video_result_id`。
- `backend/app/modules/image_generation/service.py` 的 `TaskResultStore` 和 `repository.py` 的按用户查询可复用；原图片读取服务只接受 PNG/JPEG，因此需要独立视频读取入口。
- `backend/app/modules/conversations/service/service.py` 把 `AgentResponse.image_result_id` 存入消息 `parts`；`frontend/src/features/digital-human/DigitalHumanPage.tsx` 在流完成后刷新消息。
- `backend/app/infrastructure/storage/aliyun_oss.py` 已支持上传和读取对象；当前 `get_object` 返回完整字节，不支持范围读取。首版限制视频大小并完整返回 MP4；如实际文件大小或拖动体验不能接受，再单独设计分段读取。

流程：`用户描述 → 数字人 generate_video 工具 → 创建本地任务 → 提交百炼任务 → 按 task_id 轮询 → 下载 MP4 → 私有 OSS → 完成任务 → video_result 消息 → 对话框播放`。

百炼 HTTP API 使用异步任务：创建时带 `X-DashScope-Async: enable`，随后查询任务状态，成功后获取 `output.video_url`。视频链接和 task_id 的有效期均为 24 小时，应及时保存；轮询间隔按官方建议使用 15 秒。模型、密钥和工作空间地址须同地域。[百炼 API 文档](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)

## 接口和数据影响

| 接口 | 变更 | 原因 |
|---|---|---|
| `POST /api/conversations/{conversation_id}/messages/stream?voice=true` | 路径不变；完成后的持久化消息可包含 `video_result` | 复用数字人现有对话与 SSE，视频完成后刷新消息。 |
| `POST /api/conversations/{conversation_id}/answers/stream?voice=true` | 同上 | 用户回答题卡后仍可生成视频。 |
| `GET /api/conversations/{conversation_id}/messages` | 增加可选 `video_result` part | 历史消息可恢复视频播放；原有 part 不变。 |
| `GET /api/digital-human/task-results/{task_result_id}/video` | 新增 | 校验登录用户和任务归属，成功返回 MP4；无权、未完成或不存在返回 404。现有图片接口仅接受图片，不能播放视频。 |
| `GET /api/v1/task-results/{task_result_id}/image` | 保持不变 | 继续服务原图片。 |

数据库不新增表、字段或迁移。复用 `task_results.id/user_id/conversation_id/skill_code/result` 和 `messages.content`：任务 `result` 保存状态、百炼 task_id 及成功后的 OSS object_key；消息 `content.parts` 保存 `video_result`、任务 ID 和视频读取地址。保留已有图片数据结构。OSS 对象使用视频专属前缀和 `video/mp4` 内容类型。

## 实施与验收

1. **接入百炼**：实现提交、按 task_id 查询及视频下载。验收：一次请求只创建一个百炼任务；`PENDING/RUNNING` 继续轮询，成功读取 `video_url`，失败返回明确提示；外部调用有超时，日志不记录密钥和带签名地址。
2. **保存与读取**：创建本地任务，成功后上传私有 OSS 并写入对象键；新增有用户归属校验的视频读取接口。验收：本人可读取成功视频，其他用户和失败任务不能读取；视频内容类型正确。
3. **对话接入**：注册工具，映射本轮任务 ID，持久化 `video_result`。验收：生成成功后当前消息和重新打开的历史消息都能播放；普通对话不重复显示上一轮视频；失败不展示成功播放器。
4. **页面展示与回归**：对话框使用原生视频控件播放。验收：视频有播放与暂停控件，文本、语音、题卡及原图片展示保持现有行为。

计划验证：使用模拟百炼响应覆盖提交、轮询和失败；使用模拟 OSS 验证保存与用户隔离；运行数字人及原图片相关回归测试、前端类型检查和播放器组件测试。真实百炼联调会产生费用，仅在配置齐全并明确进行联调时执行。本方案阶段尚未执行这些验证。

## 运行边界

- 首版使用当前数字人请求执行流程，在工具内等待异步任务；不新增后台恢复框架。断线、停止或服务重启时，百炼任务可能仍运行并计费。持久化百炼 task_id 供排查，不能声称服务重启后会自动恢复；用户重新提交会产生新任务。
- 完整读取视频会占用与文件大小相关的服务器内存；实施时设置明确大小上限。需要大文件流式播放或可靠拖动时，另行增加 Range 支持。
- 视频读取接口必须做任务所有权校验；临时百炼地址不写入用户消息或日志。
