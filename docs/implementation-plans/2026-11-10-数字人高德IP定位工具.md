# 数字人高德 IP 定位工具实现方案

> 日期：2026-11-10
> 状态：已按方案实施；生产代理来源仍需按部署网络配置
> 需求确认：按用户已给出的范围与代码库现状形成方案；代理入口地址作为部署配置项

## 1. 目标与背景

- **要解决的问题：** 数字人目前不能基于当前请求用户的公网 IP 查询大致位置。
- **功能目标：** 增加 `get_user_location` 工具，由模型根据用户询问当前位置、省份或城市的意图决定是否调用高德 IP 定位 API。
- **预期最终效果：** 用户询问“我现在在哪个城市？”时，数字人读取当前 HTTP 请求的可信客户端 IPv4，向高德 v3 IP 定位接口查询并据实回复；回答明确说明位置由 IP 估计。普通聊天不调用该工具。无法取得支持的 IP 或上游定位失败时，数字人说明无法定位，不猜测，也不使用服务器 IP 代替。

## 2. 已确认需求

- **使用者 / 调用方：** 登录用户通过数字人会话与助手对话；LangGraph 工具节点执行定位工具。
- **触发方式：** 模型按用户自然语言意图决定调用；只用于查询当前对话用户的位置。
- **输入：** 服务端从 FastAPI 当前请求解析出的客户端 IP。模型工具参数中不包含 IP。
- **输出：** `province`、`city`、`adcode`、`success`；失败时包含面向模型的非敏感 `message`。
- **主流程：**
  1. FastAPI 从可信代理处理后的 `Request.client.host` 获取客户端地址。
  2. 入口校验地址，只将公网 IPv4 传入本轮对话运行上下文；无效、非公网或 IPv6 地址不调用高德。
  3. 数字人图注册 `get_user_location`；模型只在用户询问自己当前所在地时调用。
  4. 工具从本轮服务端运行配置读取 IP，调用 Provider；Provider 使用 `AMAP_API_KEY` 和显式 `ip` 参数请求高德。
  5. 工具把经过筛选的位置字段或可解释失败结果交回模型，模型说明 IP 估计属性。
- **业务规则与边界：** 只返回高德实际解析出的省份、城市和 adcode；不推断缺失字段，不返回精确街道或门牌，不查询任意其他人的 IP。
- **异常行为：** 未配置 Key、客户端地址不支持、HTTP 超时或网络异常、高德返回失败、响应格式错误、位置字段均为空时，工具返回 `success: false` 和明确但不含密钥的说明。城市为空但省份有效时只允许报告省份，不声称已确定城市。
- **权限与数据范围：** 工具无模型可控 IP 参数；IP 来自当前请求且仅在该轮运行内传递。IP 不写入会话消息、业务数据库、Redis 运行记录或 LangGraph 图状态。
- **约束：** 使用现有 Python、FastAPI、LangGraph、LangChain、httpx；不新增依赖、表或前端改动；Provider 代码放到 `digital_human/providers/` 下新建的高德目录。

## 3. 范围

- **本次包含：** 高德 v3 IPv4 IP 定位、工具注册与提示词规则、请求 IP 安全提取和逐轮传递、API Key 配置、Nginx/Uvicorn 可信代理配置、Mock 测试及本地配置文档。
- **本次不包含：** GPS 或浏览器定位、地图展示、附近搜索、任意 IP 查询、数据库持久化、前端 UI 改动、高德高级 v5 定位。

## 4. 需求澄清记录

需求和代码库信息已足够形成方案。代理拓扑按可配置方式处理：部署者需将 Uvicorn 的 `FORWARDED_ALLOW_IPS` 配置为实际可信 Nginx 上游地址；仓库没有 Nginx 容器或生产网段声明，因此方案不硬编码 Docker 网段。当前 Nginx 配置假设其直接收到客户端连接；若前面还有 CDN 或负载均衡器，应另行按其可信地址配置 Nginx real-IP 处理。

## 6. 架构设计

### 模块职责与边界

| 模块 | 职责 | 依赖方向 / 边界 |
|---|---|---|
| 对话依赖与 Router | 从 FastAPI 请求取得 ASGI 客户端地址，并将依赖结果交给现有 Service | 不读取原始 `X-Forwarded-For`；不包含高德业务请求 |
| ConversationService | 在 `PreparedConversationTurn` 中临时保存本轮 IP，并随现有 `RunnableConfig.configurable` 传给数字人 Runtime | 只向 `digital_human` 配置 IP；不持久化 IP |
| 数字人工具 `get_user_location` | 接收 LangChain 隐式注入的运行配置、调用 Provider、形成工具 JSON 结果 | 工具 schema 不含 IP；不负责解析 HTTP 请求或实现高德协议 |
| `providers/amap` | 用 httpx 请求高德、校验响应并将上游错误转换为不泄露凭据的结果/异常 | 依赖 Settings 与 httpx；不依赖 Agent、Router 或数据库 |
| Settings / 部署配置 | 从环境变量读取 API Key；将可信代理源限制配置传给 Uvicorn | API Key 仅后端读取；代理允许列表按部署入口设置 |

### 关键流程

```text
HTTP Request
  -> Uvicorn ProxyHeadersMiddleware（只信任 FORWARDED_ALLOW_IPS 中的代理）
  -> Request.client.host 公网 IPv4 校验
  -> PreparedConversationTurn（仅本轮内存快照）
  -> RunnableConfig.configurable.client_ip
  -> LangGraph ToolNode 注入配置
  -> get_user_location（模型工具参数不含 IP）
  -> providers/amap 使用 AMAP_API_KEY 和显式 ip 调用高德 v3
  -> 筛选位置字段或安全失败结果
  -> 模型按 IP 估计规则答复
```

选择 `RunnableConfig.configurable` 是因为数字人现有图片、视频、提醒等工具已通过此配置取得服务端用户/会话信息，且 Runtime 会复制并保留 configurable；ToolNode 会把当前调用配置注入工具。IP 只增加到当次执行参数，不写入消息状态。Provider 始终显式传 `ip`：高德 v3 文档说明省略 `ip` 时会用调用方 HTTP 请求定位，可能错误定位到服务器。该接口只支持国内 IPv4，局域网、非法或海外地址可能返回空位置，工具必须把这些结果当作不可定位。[高德 IP 定位 API 文档](https://lbs.amap.com/api/webservice/guide/api/ipconfig)

### 代理与 IP 信任

- FastAPI 依赖只读取 Uvicorn 处理后的 `request.client.host`，用标准库 `ipaddress` 验证公网 IPv4；不从业务代码直接读取或挑选 `X-Forwarded-For` 链中的任意元素。
- Uvicorn 支持通过 `FORWARDED_ALLOW_IPS` 限定可信来源。Compose 将该环境变量显式传入后端，默认仅含 loopback；生产部署必须覆盖为**实际连接后端的 Nginx 来源 IP**，不使用 `*` 或宽泛网段。
- Nginx 的后端代理配置将 `X-Forwarded-For` 设为 `$remote_addr`，不沿用不可信请求头中的既有链。若存在前置 CDN/LB，需先由 Nginx 按显式可信来源还原客户端 IP；当前仓库没有此前置层配置。
- 后端直接连接时，以 socket peer 为客户端地址。公网部署可将后端端口限制在可信网络；Compose 开发环境仍允许本机访问。

### 高德 API 与工具结果

- URL：`https://restapi.amap.com/v3/ip`；HTTP GET 参数固定包含 `key`、已校验的 `ip` 和 `output=json`。
- 仅接受有效成功状态及非空位置字段。`province=局域网`、`city/province` 均空、API 失败、无效 JSON、网络错误或超时均形成失败结果。
- 若只有省份有效，工具仅返回该省份，城市保持空值；LLM 不得补猜城市。
- 返回给模型和日志的内容不含 API Key，不返回原始请求 URL、完整上游响应或客户端 IP。
- 普通聊天是否调用定位由模型工具选择决定；系统能力规则明确：只有用户问“我现在在哪里/在哪个城市或省份”等当前用户定位意图时调用，普通对话不调用。

| 接口（方法 + 路径 / 事件） | 操作 | 当前定义位置 | 变更前后契约 | 复用判断与变更理由 | 兼容性 / 调用方影响 |
|---|---|---|---|---|---|

| `conversations` 全部字段 | 保持不变 | `backend/app/modules/conversations/models/models.py`：`Conversation` | 会话归属、技能和标题不因定位改变 | 无需保存客户端 IP 或位置缓存 | 无迁移 |
| `messages` 全部字段 | 保持不变 | 同上：`Message` | 继续保存用户消息和助手可见回答；不保存原始 IP | JSONB 内容结构已足够承载普通文本答复，无须新增位置字段 | 无迁移 |
| LangGraph Checkpointer 状态 | 保持既有结构 | `backend/app/infrastructure/database/checkpointer.py` 及数字人图 | 保存原有对话状态；IP只进入本轮运行配置，不进入 graph messages/state | 需求不要求历史定位或跨轮缓存 | 无 Checkpointer schema 迁移 |

**结论：无数据库变更。**

### 最小变更结论

- **可复用的现有接口 / 数据结构：** 现有对话入口、`PreparedConversationTurn`、`RunnableConfig.configurable`、`ToolNode`、数字人工具列表与能力提示词。
- **本方案实际新增或修改的最小集合：** 一份 Provider 客户端、一个 LangChain 工具、一个请求 IP 依赖、现有对话链的内部上下文传递、Settings/部署配置、测试和配置文档。
- **排除的冗余设计及原因：** 不新增独立定位 Service 或业务模块；外部 HTTP 适配由用户指定的 `providers/amap` 承载，工具直接调用 Provider。无需新增 IP 缓存、数据库字段、API 路由、前端状态或第三方依赖。
- **尚未确认的接口或数据决策：** 无。部署时 `FORWARDED_ALLOW_IPS` 的具体值取决于 Nginx 到后端的实际网络来源，按环境配置而非写死在业务代码。

## 10. 分步实施计划

### 步骤 1：配置 API Key 与代理信任边界

- **目的：** 让高德凭据只在服务端可用，并保证 ASGI 客户端 IP 来自可信连接。
- **涉及文件：** `backend/app/core/config.py`、`.env.example`、`docker-compose.yml`、`deploy/nginx/orionai.conf`、`docs/development/local-setup.md`。

- **前置依赖：** 无。
- **验收标准：**
  - [ ] `AMAP_API_KEY` 可从环境变量读取，Settings repr/错误/日志中不呈现密钥明文。

### 步骤 2：实现高德 Provider 与失败边界

## 12. 风险、假设与运行考虑

- **非阻塞假设：** 当前 `deploy/nginx/orionai.conf` 中 Nginx 是直接客户端入口；若前置 CDN/LB，应只信任其官方/运维配置的来源地址并让 Nginx 正确解析真实客户端 IP。
- **代理配置风险：** `FORWARDED_ALLOW_IPS` 的正确值依赖后端 socket 实际看到的代理地址，尤其 Docker host-port 场景。错误配置会造成 IP 定位不可用，但不应通过扩大信任网段或信任 `*` 修复；部署时根据连接来源配置精确地址。
- **定位精度：** Amap v3 只支持国内 IPv4；IP 位置是运营商/出口网络估计，VPN、公司 NAT 和移动网络可能使城市与用户实际位置不同。回答必须表述为估计。
- **隐私与日志：** 不记录原始客户端 IP、完整高德 URL 或 API Key；调试仅记录错误类型/高德错误码等非敏感信息。IP 保留在当前请求与 Agent 执行内存中，不写入持久数据。
- **性能：** 仅模型选中工具时进行一次有超时的外部请求；不做无依据重试，不缓存跨请求 IP 或位置。
- **发布 / 回滚：** 无数据库迁移。回滚时移除工具注册与配置转发即可；环境变量保留为空不影响其他功能。Nginx 与 Uvicorn 配置回滚需同步恢复前确认代理安全要求。
